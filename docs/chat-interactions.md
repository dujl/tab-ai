# 在聊天里审批和回答问题

tab-ai 0.3.0 优先使用交互卡片。按钮只对应 agent 当前发出的请求，不会改写提示词或新增一轮用户消息。单次与本会话授权按原生能力展示，策略修改与临时授权的范围见 [本会话审批](session-approvals.md)。

| 入口        | 审批                                    | 单选 / 多选            | 自定义回答                           |
| ----------- | --------------------------------------- | ---------------------- | ------------------------------------ |
| 飞书 / Lark | 按请求展示本次 / 会话内允许、拒绝和取消 | 下拉选择并提交         | 表单输入框，按原生请求是否允许显示   |
| 钉钉        | 模板按钮                                | 模板的单选 / 多选组件  | 模板输入框；需要先配置本租户模板     |
| 企业微信    | 按请求展示本次 / 会话内允许、拒绝和取消 | 原生投票选择卡片       | 使用文字命令或本地 Web 工作台        |
| 微信        | `/tab approve` 文字命令                 | `/tab answer` 文字命令 | 引用相应子会话提示回答，或使用工作台 |
| 本地 Web    | 按请求展示本次 / 会话内允许、拒绝和取消 | 单选按钮 / 多选框      | 输入框，按原生请求是否允许显示       |

Codex 当前适配的 requestUserInput 协议是单选 / 自由输入；不会擅自将它变成多选。Claude Code 的 multiSelect 标志决定是否显示多选。选项说明完整保留；企微投票模板不能承载选项说明时，先发送一条说明，再发送选择卡片。

每个问题对应一张卡片。多题会显示题号，全部提交后才通过原生协议恢复等待中的 agent。已提交的一题不可再次修改；需要改动时应停止当前任务再重新说明。卡片不会默认替用户选中任何答案。

### 飞书异步提问

Codex 的 `request_user_input_async` 会在完成的 `agentMessage` 中携带 `delivery: async` 和结构化 `questions`。飞书将这类消息展示为选择 / 自定义回答卡片，不再重复转发同一份文字选项。普通文本列表不会被猜测为选择题。

异步提问不会把会话改成等待状态，Agent 继续分析。提交后，运行中的原轮次通过 `turn/steer` 接收回答，附带预期轮次 ID；如果该轮已确认结束，则恢复同一个原生会话进行下一轮。不会重放原任务，也不会新建原生上下文。只有一个待回答的异步问题时，也可直接回复完整选项或序号；自由文本和多题可用卡片表单或 `/tab answer`，不经过意图模型猜测答案。

问题沿用交互超时（默认 10 分钟），超时不代答、不停止分析。停止 / 关闭 / 重置会话、切换目录、交还终端或开始新的普通任务，会撤销旧问题；服务重启后旧卡片同样无效。回传失败或结果未知时提示用户，不自动重试或另起一轮。权限、来源会话和原卡片消息校验与同步提问相同。其他通道的异步提问展示保持原有文字行为。

## 飞书 / Lark 配置

新应用扫码创建时会请求预填 `card.action.trigger` 回调订阅。预填是否生效取决于平台开放范围。

已有应用请在开放平台的「事件与回调 → 回调配置」中，选择长连接，添加「卡片回传交互 card.action.trigger」，保存并发布版本。它与接收消息的 `im.message.receive_v1` 事件配置不同。卡片能收到但点击无反应时，优先检查这一项。

实现使用 `im.message.reply/create` 发送 interactive 消息、`im.message.patch` 更新状态；无需公网回调地址。消息/卡片的发送仍需要机器人的消息权限。

依据：[官方卡片回调结构](https://open.feishu.cn/document/feishu-cards/card-callback-communication)、[官方表单容器](https://open.feishu.cn/document/feishu-cards/card-components/containers/form-container)。

## 钉钉模板准备

钉钉模板目前只承载“允许本次/拒绝”。原生请求提供会话范围、取消或缺少这两个决定时，使用完整文字命令保留实际选项。互动卡片需要本租户可用的卡片模板和「互动卡片实例写权限」。tab-ai 不使用不可控的公共示例模板。未填模板 ID 时直接发送文字题目和答题命令；普通聊天功能仍可使用。

在钉钉卡片平台创建关联本应用的模板，按下表声明变量并布局组件。下述是 tab-ai 的模板契约，不是可直接导入的钉钉卡片 DSL。模板需要在平台编辑器中配置并验收。

| 变量名       | 传入类型               | 含义                                                 |
| ------------ | ---------------------- | ---------------------------------------------------- |
| title        | 字符串                 | 原生请求标题                                         |
| body         | 字符串                 | 审批的程序摘要，或完整题目与选项说明                 |
| kind         | 字符串                 | approval 或 question                                 |
| options      | JSON 数组的字符串      | 选项，数组项为 text / value；value 是从 0 开始的索引 |
| multiSelect  | 字符串                 | true / false                                         |
| allowOther   | 字符串                 | true / false                                         |
| status       | 字符串                 | 待处理、已提交、已允许本次操作、已拒绝本次操作等     |
| hint         | 字符串                 | 文字兜底提示；审批含 `/tab inspect <ID>` 原文入口    |
| detailAction | 字符串                 | 常量 `details`，可供查看完整请求按钮绑定             |
| progress     | 字符串                 | 题号 / 总数                                          |
| feedback     | 字符串（用户私有数据） | 拒绝操作或校验错误提示，初始为空                     |

组件与回传：

1. 用文本组件显示 title、body、progress、hint、status；不要将操作详情仅作为隐藏回传字段。
2. `kind == approval` 且 `status == 待处理` 时显示「允许本次」「拒绝」。点击事件类型选择「回传请求」，参数 `action` 分别为常量 `allow` 和 `deny`。另加「查看完整请求」按钮，`action` 为 `details`（或绑定 detailAction），此按钮只投递原文，不提交批准。已有模板未增加第三按钮时仍可按 hint 中的 `/tab inspect` 查看。
3. `kind == question` 且 `status == 待处理` 时显示选择组件。将 options JSON 解析为选项集合，text 为显示名称，value 为回传值；按 multiSelect 切换单选 / 多选。不要设置默认选中项。
4. allowOther 为 true 或 options 为空时提供文本输入。用户在选项与自定义文本之间二选一，不能同时提交。
5. 「提交回答」回传参数：`action` 为常量 `submit`，`selection` 绑定所选 value（单选字符串、多选字符串数组），`text` 绑定自定义输入；没有填写的字段可省略或为空。
6. 接口收到的内容应为 `content.cardPrivateData.params`。status 不再等于「待处理」时隐藏所有操作控件；feedback 显示给当前操作用户，不覆盖全员卡片。

回调内容示例（content 在线上是 JSON 字符串）：

```json
{
  "cardPrivateData": {
    "params": { "action": "submit", "selection": ["0", "2"] }
  }
}
```

保存模板后，将 ID 填入 CLI / 网页接入向导的「钉钉卡片模板 ID」。已有机器人可在其 channels 配置条目添加 `cardTemplateId` 并重启服务：

```json
"cardTemplateId": "你的模板ID.schema"
```

投递通过 `/v1.0/card/instances/createAndDeliver`，`callbackType: STREAM`；回调通过 `/v1.0/card/instances/callback`，与机器人消息共用官方 Stream 客户端。模板不合规、未授权或投递失败时回退文字；客户端无回调时发送 `/tab pending`。当前模板变量和回调格式已完成模拟测试，实际模板布局与租户授权需在钉钉客户端验收。

依据：[钉钉官方卡片回调教程](https://open-dingtalk.github.io/developerpedia/docs/explore/tutorials/stream/bot/go/card-callback/)、[官方 Python SDK 卡片实现](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/main/dingtalk_stream/card_replier.py)。

## 企业微信

使用智能机器人 API 长连接模式；按钮交互和投票选择均走官方 SDK。每题最多 20 个选项；自由文本题、超出卡片长度/数量限制的题目使用完整文字答题方式，不裁掉选项或默默替用户选择。

企微允许在点击回调中更新卡片，更新仅面向操作者。超时、停止或在 Web/文字端作答后，本机立即撤销卡片的授权能力；企微旧卡片可能暂时仍显示按钮，再点会提示已经结束，不会重跑任务。服务重启后旧卡片同样无效。

依据：[企业微信官方智能机器人 SDK](https://github.com/WecomTeam/aibot-node-sdk)、[官方插件的模板卡片回调结构](https://github.com/WecomTeam/wecom-openclaw-plugin/blob/main/src/message-parser.ts)。

## 文字兜底、权限和恢复

- 发送 `/tab pending` 查看当前会话的审批摘要、待回答问题、选项说明以及带实际请求 ID 的答题命令。`/tab inspect <请求ID>` 单独查看对应请求的完整原文和处理状态，已结束的审批仍可查询；不提交或重新执行决定。已有 `/tab approve` 和 `/tab answer` 继续可用。
- 不支持卡片或卡片投递失败时自动回退文字，不重新执行模型任务。结果不确定的卡片发送不自动重试；卡片可能曾出现，但本机已撤销相应回调授权。
- 回调必须来自平台认证的长连接，且操作者为原任务发起人、来源为原会话；飞书进一步匹配原卡片消息 ID，钉钉匹配投放场域与 staff ID。
- 仍检查当前白名单。重复点击、选项越界、单选提交多个答案、未知问题、已完成或过期请求均不会放行。
- 请求默认等待 10 分钟，可受整轮任务剩余时间限制。超时、停止及重启均不自动批准；重启不会恢复正在等待的原生 RPC，应重新恢复会话发起任务。
- Web 工作台持有本机管理令牌，可以代表本机所有者回答；聊天其他用户不能代答。
- 登录、敏感输入以及未适配的原生交互仍使用原生终端。

## 验收范围

自动化覆盖三平台渲染与回调、官方 SDK 分发、操作者/来源校验、重复与过期提交、部分答题聚合、投递失败降级、取消期间迟到的投递和原生答案回传。测试不需要真实模型或平台凭证。

尚需真实租户验收：三平台卡片展示和点击、飞书回调订阅、钉钉模板字段绑定/权限、企微群聊更新效果。桌面与 390 像素移动浏览器已验证摘要、完整原文折叠、轮询保留展开状态、拒绝原请求及无横向溢出。真实 IM 客户端排版和租户配置仍需验收，不把模拟回调测试视为真实客户端验收。

## 命令审批展示

Codex、Claude Code 和 OpenCode 共用审批展示：首屏分别显示会话默认目录与原生请求提供的本次执行目录，并显示操作类型、执行器，以及请求中明确出现的网络域名、文件或权限范围。长脚本不在首屏整段打印。例如 `zsh -lc "python3 -c …"` 展示「执行 Python 内联脚本（N 行）」、`zsh → python3` 和网址中识别到的域名；不会仅凭脚本出现 URL 就断言它只联网或不会修改文件。Agent 提供的申请原因明确标为 Agent 申请原因。

摘要由本工程的确定性规则提取，不调用大模型，不运行命令，也不是完整影响分析。遇到 shell 组合语法或未识别工具时保守显示复合命令 / 原生工具请求，提示查看完整请求；OpenCode 只有权限匹配规则时，不把通配符伪装成实际执行命令。额外权限优先显示；过长字段和其他参数有明确的详情入口。

工具可以为单次调用指定其他目录，例如进入工作树或子项目；这不会修改会话默认目录。目录不同时明确提示，审批沿用原生请求，不将其改写成会话路径。原生未提供 cwd 时标记“原生未单独提供”，会话目录只作参考，不冒充已确认的实际执行目录。

- **飞书 / Lark**：纯文本摘要和「允许本次 / 拒绝 / 查看完整请求」按钮。查看后后台将原始完整详情发送到原聊天 / 原话题，回调立即确认，不等待长内容投递。
- **企业微信**：短操作摘要、执行目录与会话目录、权限 / 执行器 / 目标和审批编号；点击「查看原文」后才分段发送完整详情，先响应卡片回调，再发原文。
- **钉钉**：body 为程序摘要，hint 带 `/tab inspect`；本租户模板可增加 action=details 的查看按钮。没有更新模板时文字原文入口仍可用。
- **Dashboard**：摘要和字段列表，完整原文放在默认收起的「查看完整请求」中；相同请求的普通轮询不会收起用户已展开的详情。
- **文字渠道 / 卡片兜底**：先显示摘要、`/tab inspect <请求ID>` 和允许 / 拒绝命令，按需查看完整原文。

完整命令、目录、文件变更、额外权限和未知业务参数仍保存在 Interaction.detail 与审批分区中；仅隐藏 Codex threadId 等传输标识和未启用的持久授权替代选项。原文不经模型重写、不截断；超出传输限制时逐 Unicode 字符按字节预算分段，附同一审批编号。企微原文使用独立代码围栏保留特殊字符。审批权限、单次允许 / 拒绝的原生决策与超时行为均不变。

查看原文必须通过同样的发起人、来源会话、卡片消息 / 投放场域与期限校验；已结束或过期卡片不能再查看或批准。后台详情队列最多 16 项，同话题串行，重复点击在投递期间合并；每项投递最多等待 30 秒。失败或结果未知时停止后续分片，记录请求 ID，并尝试在原会话提示失败；不自动重发原文，不影响审批结果。停止渠道会取消队列。

## 通用管理入口

`/tab menu` 按通道展示原生卡片或可复制的命令菜单，覆盖状态、目录、模型、历史、任务、附件等入口；管理按钮不进入工作 Agent 上下文。详见[跨通道管理菜单](management-cards.md)。

## 企微审批点击反馈与诊断

企微客户端按钮的点击状态不代表框架已经批准。有效操作须经原发起人、来源聊天、有效期与当前白名单校验，再由原生协议接收；可用交互记录中的 `decision` 与后续工具事件核对。

拒收、过期、已提交或重启后的旧卡片，向本次平台回调所在群聊反馈，不再把群内错误发往个人单聊；同时尝试仅更新操作者看到的卡片，显示“本次点击未生效”。更新失败仍尝试发送群内文字。原生决定已提交而卡片更新失败时，反馈已提交的状态，不重新批准或重跑工具。

日志区分收到回调、格式不识别、有效提交、结束/过期、来源/权限拒绝、卡片显示更新失败，以及连接、心跳、平台拒绝与回执超时。记录时间、审批与卡片的关联 ID；用户和聊天仅保留散列，不记录原始回调、凭据、下载链接或完整命令。旧版合并为 channel error 的日志无法据此还原历史点击原因。

## 审批 / 提问超时的主动通知

到达交互有效期时，框架立即移除待回答请求，记录 interaction_timeout，并在审批原先投递的会话主动发送编号、标题和超时状态。通知不依赖 Agent 完成，也不等待用户再次点击；不附带完整命令，不自动批准或重跑工具。

飞书卡片更新为红色，标题显示“审批已超时，未批准”，原按钮移除；钉钉已配置模板更新状态。卡片更新失败仍尝试投递文字通知。企微无法主动替换已有卡片，因此主动在原群 / 原单聊提示“旧卡片已失效”；后续点击同样不能放行。子任务汇总到主任务的审批，其超时通知也跟随到主任务话题。

异步提问超时会通知用户但不会停止后台分析；不会把提问超时表述成工具审批。普通停止 / 取消与超时分开处理。迟到的卡片投递会立即失效，避免补发新的可用批准入口。原生 Codex 超时异常保留到框架，不额外重复一条相同的通用超时错误。

## 飞书卡片的状态表达

工具执行和审批卡片同时在标题显示状态文字与颜色，不能只靠颜色区分：

| 颜色 | 表达的状态                                       |
| ---- | ------------------------------------------------ |
| 橙色 | 待审批；整轮含部分失败调用，或部分结果未确认     |
| 蓝色 | 工具执行中；等待回答                             |
| 绿色 | 已允许本次操作；回答已提交；确认全部工具执行成功 |
| 红色 | 已拒绝；工具执行失败；审批或提问超时             |
| 灰色 | 审批/提问已结束且未批准，或执行已中断            |

审批绿色明确标注“已允许 · 待执行结果”，不表示工具已经执行成功。本轮结束但缺少工具完成事件、存在未确认结果或早期调用超出保留范围时，工具卡片使用橙色提示，不能显示为全部成功。原卡片回调与结束更新使用同一套状态映射，审批授权及超时规则保持不变。其他通道按各自模板能力显示状态文字，不假设支持飞书的标题配色。

设计依据见[设计原则与实现](design-principles.md)，代码见[状态映射](https://github.com/dujl/tab-ai/blob/main/src/channels/lark-card-status.ts)。
