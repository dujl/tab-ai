# 钉钉接入与消息收发

tab-ai 使用企业内部应用的 Stream 机器人，无需公网回调地址。支持文字单聊、群内 @ 机器人、虚拟子会话和 Markdown 管理菜单。安装与向导入口见 [首次接入](onboarding.md)；审批、提问卡片需要另配 [租户模板](chat-interactions.md#钉钉模板准备)。

## 扫码接入（推荐）

1. 执行 `tab-ai setup`，选择「钉钉 → 扫码创建 / 绑定」。网页向导选择钉钉后也默认提供扫码方式。
2. 用手机钉钉扫描向导显示的二维码，按官方页面确认创建或绑定机器人。Client ID 和 Client Secret 自动保存，无需手工复制或编辑配置。
3. 扫码完成后，使用自己的钉钉账号私聊机器人发送「你好」。收到测试回执后，回到向导核对账号并确认启用；确认前不会运行 Agent。
4. 在机器人私聊发送 `/tab status` 或 `/tab menu` 测试管理回复，再发送普通问题测试 Agent。群聊测试需将机器人加入所属组织的测试群，使用 @ 发送消息。

扫码注册使用 [钉钉官方连接器的 Device Flow 协议](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector/blob/main/bin/dingtalk-connector.js)，不需要安装 OpenClaw。授权会话、二维码和轮询均由钉钉官方接口提供。租户的创建权限、审批和最终授权以手机确认页为准；扫码后仍需真实消息验证收发。链接过期可重新扫码；已取得凭证但尚未启用的接入可选择「继续未完成配置」，无需重复创建机器人。

向导生成带工程名的建议名称（如 `tab-ai-bot1`），保存为 tab-ai 中的显示名；编号与飞书接入共用当前实例的递增序列，继续未完成配置时保留原名。当前采用的官方扫码协议没有公开名称预填参数，因此不会自动改写钉钉客户端中的机器人名称。创建时可在官方页面填写建议名称；已有机器人可在钉钉开发者后台的机器人配置中修改名称，并按平台提示发布生效。

扫码接入无需配对命令，首条有效私聊仅作为待确认账号，必须在本机向导核对并确认后才启用。群消息、空白消息不参与配对。卡片模板留空即可使用文字审批和答题；自定义卡片可稍后按 [模板指南](chat-interactions.md#钉钉模板准备) 配置。

## 手动接入已有机器人

1. 在 [钉钉开发者后台](https://open-dev.dingtalk.com/) 创建企业内部应用，添加机器人能力。
2. 消息接收选择 Stream 模式，发布应用并设置可用范围；群聊使用时将机器人加入目标群。
3. 长任务主动回复需要机器人发送消息权限，分别按官方 [单聊发送](https://open.dingtalk.com/document/orgapp/chatbots-send-one-on-one-chat-messages-in-batches) 与 [群聊发送](https://open.dingtalk.com/document/orgapp/the-robot-sends-a-group-message) 接口文档申请对应权限，再重新发布，使租户授权和可用范围生效。
4. 执行 `tab-ai setup`，选择钉钉，填写 Client ID（AppKey）和 Client Secret（AppSecret）。卡片模板 ID 可留空。
5. 使用自己的账号私聊机器人发送向导给出的配对命令；收到双向连接回执后，回到向导核对身份并确认启用。该用户随后加入允许列表。

配对码只接受单聊。普通群消息需要 @ 机器人；群全量模式和飞书原生话题不适用于此通道。独立子会话使用 `/tab to` 等虚拟路由，回复仍投递到原聊天。

## 消息排版

管理消息使用钉钉 Markdown：标题、会话摘要、正文和操作命令分区显示。菜单显示 Agent、模型与工作目录摘要；`/tab status` 展示完整状态字段。操作以准确的命令呈现，复制发送即可，不模拟可点击按钮。

自然语言回答含标题、加粗、列表或链接时使用 Markdown，普通短句仍发送文本。HTML 标签按文字显示。平台明确拒绝 Markdown 时才回退文字；超时或发送结果未知不会自动重发。超长消息按转义后的 UTF-8 字节数分段。

可点击、可更新的互动卡片需要钉钉卡片平台模板和权限；当前可选模板用于审批和答题，不自动充当管理菜单或 AI 流式回答卡片。模板配置见 [聊天交互](chat-interactions.md#钉钉模板准备)。Markdown 的客户端外观及各格式支持范围仍需在实际钉钉客户端验证。

## 长任务回复

自然语言任务通过权限、去重及运行状态检查后，会先收到一次「已收到，正在处理」提示，再按顺序收到 Agent 的公开回复。首次启动 Agent 可能较慢；可发送 `/tab status` 查看状态，或 `/tab stop` 中断。提示不代表任务完成；提示发送失败不会阻止任务执行，也不会自动重发或重跑任务。Slash 管理命令仍直接回复，不增加任务提示。

收到消息后，tab-ai 保存该聊天的临时 `sessionWebhook`，正常回复优先使用尚未过期的地址。地址和签名仅保存在当前进程内存中，不传入模型或对话记录。

回复地址缺失或已过期时，使用应用 access token 主动发送：群聊投递到回调确认的原 `conversationId`；单聊使用回调中的 `senderStaffId`。不会把不透明的 `senderId` 当作 staff ID，也不会在群聊失败后改发单聊。Markdown 管理菜单同样支持过期后的主动发送，无需卡片模板。应用令牌在有效期内复用，并发请求共享一次刷新。

主动发送需要当前进程接收过该目标的消息，且回调提供 `robotCode`，单聊还需要 `senderStaffId`。服务重启后内存中的回复目标需要新消息重新建立；缺少目标时会明确提示在原聊天发送 `/tab last`，不会猜测收件人。成功受理响应包含 `processQueryKey`，代表平台已受理请求，不等于用户已读。

每段消息独立检查回复地址有效期。文字按 UTF-8 字节数分段，保留中文、表情和换行。网络超时、HTTP 失败、无效响应或主动发送结果未确认时不会自动重发，也不会切换其他投递路径重复发送。Webhook 明确拒绝 Markdown 时可回退为文字菜单。

## 回执、重连和排障

- Stream 回执在文本归一化并交给框架后返回，不等待模型分类或任务执行结束。平台重投消息仍由框架按机器人及消息 ID 持久去重；回执表示收到消息，不表示任务完成，也不提供接收与外部副作用之间的分布式事务保证。
- 不支持的消息类型、未 @ 的群消息和无效消息不会启动任务；无效回调也会返回回执，避免持续重投。
- 长连接的心跳、断线重连和退避由官方 SDK 处理。启动失败会断开该连接，其他机器人和网页仍可使用。启动 ready 不代表持续网络健康。
- 扫码链接过期或取消：重新开始扫码；若已取得凭证，选择「继续未完成配置」，避免重复创建。
- 配对收不到消息：扫码接入发送「你好」，手动接入发送向导给出的配对命令。检查 Stream 模式、应用发布、可用范围、本人是否能私聊机器人。群聊再检查机器人是否入群并被 @。
- 短任务能回复，长任务无法回复：检查单聊/群聊发送权限、应用发布及租户范围；主动接口可能受平台限流和调用额度限制。
- 提示缺少主动发送目标：在原聊天发送 `/tab last` 建立新的回复入口，获取已保存的最近输出。
- 卡片不可用：检查租户模板和互动卡片实例写权限；未配置模板时使用文字审批/答题命令。

当前自动化验收使用隔离 SDK 与 HTTP 替身，覆盖及时回执、去重、回复地址过期、群/单聊目标、令牌刷新和不重发未知结果。真实租户的权限、客户端展示和持续断网恢复需单独联调；自动测试不代表真实钉钉租户已验收。

接口依据：[Stream 协议](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/protocol/)、[官方 Node SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs)、[单聊发送](https://open.dingtalk.com/document/orgapp/chatbots-send-one-on-one-chat-messages-in-batches)、[群聊发送](https://open.dingtalk.com/document/orgapp/the-robot-sends-a-group-message)、[官方 SDK 请求与响应定义](https://github.com/alibabacloud-go/dingtalk/blob/v2.0.83/robot_1_0/client.go)。
