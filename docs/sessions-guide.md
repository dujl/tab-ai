# 会话、模型、指令与附件

## 主会话和独立会话

普通私聊消息复用当前用户与 BOT 的主 session，不每条新建。飞书用 `/tab new` 或“新建一个会话，设计行情系统”创建独立话题。关闭会话保留历史，不自动重新打开。

新子会话的工作目录默认继承所属主会话的当前目录，适用于命令、自然语言新建及飞书原生新话题。从已有子话题继续拆分时，继承这个直接父级的目录；明确指定工作目录时使用指定值。主会话尚不存在时使用 BOT／实例默认目录；已有子会话不随主会话后续切目录迁移。

普通会话创建后若未明确工作目录，飞书初始化卡片可能等待选择目录/附加指令。首个任务保存在 `pendingInitialTask`，点击“使用当前设置直接开始任务”或发送 `/tab begin` 才执行。已明确指定目录且有任务时可以直接启动。

对话标题可用 `/tab rename 新名称` 修改，不要求首次创建时一次确定。机器人自己创建的飞书根消息可以同步更新；用户原消息或不受控话题不能保证可改。

## 三类 ID

| ID             | 查哪里                         | 用途                           |
| -------------- | ------------------------------ | ------------------------------ |
| tab-ai 管理 ID | 卡片、Dashboard、`/tab status` | 本框架关闭/恢复/选择会话       |
| 原生 Agent ID  | 首次启动后的卡片/状态/工作台   | `codex resume` 等原生恢复      |
| 任务 ID        | 任务树、`/tab tasks`           | 定位父子任务及管理任务生命周期 |

`/tab main` 查询当前聊天的主会话 ID，不创建会话。原生 ID 显示“尚未启动”时，不能拿管理 ID 冒充原生 ID 去 resume。

## Workspace 与指令

工作目录可填预设别名或服务器上真实存在的绝对路径。它决定 Agent 的 cwd，以及原生运行时如何读取 AGENTS.md、CLAUDE.md 和项目配置。tab-ai 不把这些文件复制成第一轮用户消息；具体层级和优先级仍由各原生 Agent 实现。

“系统提示词”在产品中采用**会话附加指令**，必须和“首轮任务”区分：

- 附加指令：角色/行为约束，首次工作前设置，任务开始后固定。
- 首轮任务：本次要做什么，属于用户输入。
- 项目指令：原生 Agent 根据工作目录加载，受原生规则控制。

各聊天通道自动附加当前平台、机器人和单聊 / 群聊背景；用户附加指令仍独立保存。Codex 使用会话级 developer instructions，并保留本机已有 developer instructions；Claude 在原生 preset 上追加通道背景和用户指令；OpenCode 使用其逐轮 system 参数。未关联聊天通道且没有用户附加指令的本地会话保持原生默认。OpenCode 带通道背景或附加指令的会话暂不提供等价终端交接，以免丢失逐轮约束。

聊天可用 `/tab new codex default --instructions 你是一位严谨的架构评审者`；`/tab instructions` 只查看，不作为工作输入发送。自然语言普通新会话可按明确格式指定角色；任务编排入口的限制见[任务手册](task-orchestration.md)。

## 模型和思考深度

飞书卡片 `/tab settings` 或 Dashboard“模型 / 思考”查询当前 Agent 的模型能力。只显示后端实际提供的模型和思考档位，不为所有 Agent 硬编码同一组。

修改按 session 保存，不改变其他会话或全局原生配置，不作为对话消息插入。当前运行或等待确认时不能保存，需要等本轮结束。没有明确覆盖时沿用原生配置。模型可用性、价格和额度由原生 provider 决定。

## 审批、提问和工具记录

原生工具审批转成平台卡片或文字兜底。用户允许/拒绝只结算对应请求，不是永久授权所有命令。多题原生提问需要完整提交；答案绑定原 session 与请求 ID，并检查发送者。

`/tab pending` 查看待处理项摘要；`/tab inspect <请求ID>` 查看审批完整原文（不提交决定）；`/tab approve <请求ID> allow|session|deny|cancel` 按请求实际选项处理审批；`/tab answer <请求ID> {"问题ID":["答案"]}` 提交问题答案。重启、超时或请求结束后，旧卡片不能继续批准。

飞书与本地工作台展示“当前操作、调用次数、可折叠明细”。`/tab tools [序号]` 查询最近一轮命令/输入/结果/状态；不同平台卡片能力不同。长结果可能截断，不把界面摘要当作完整原始日志。

## 附件按需下载

收到附件只登记，不自动下载。先 `/tab files` 查看；飞书可 `/tab files sync` 同步近期旧附件列表，这一步仍不下载。

```text
/tab files download 1
/tab files download all
```

明确说“读取/下载这个附件”也可走已适配的意图识别。多个附件无法确定目标时要求选择，不猜测。下载依赖 BOT 的平台权限和文件可访问性；获得用户登录授权不一定能代替机器人应用权限。

原生 Agent 后续接收本地文件路径。不要假设微信/企微/钉钉都具备飞书相同的附件历史检索和下载能力；未适配能力会明确报错。

## 停止、关闭、恢复和终端交接

- `/tab stop`：中断当前轮，保留会话。
- `/tab close`：关闭会话，停止当前任务，保留历史；显示系统关闭通知，与 Agent 内容区分。
- `/tab open`：打开同一管理会话，等待新输入，不重跑历史。
- `/tab last`：重新发送上轮结果，不再次执行。
- `/tab inbox [短ID]`：查看钉钉尚未处理或中断的收件原文；核对后用 `/tab inbox dismiss <短ID>` 清理中断记录。容量和恢复边界见 [钉钉收件恢复](dingtalk.md#收件恢复与容量)。
- `/tab detach` 或 `tab-ai native <管理ID>`：交还原生终端。
- `/tab attach`：先退出原生 CLI，再交回框架，避免两边同时写原生 session。

任务 session 还具有任务队列状态，打开会话后可能需要 `/tab task-resume` 恢复调度。更换已经启动的工作目录通过 `/tab workspace <目录>` 或聊天内明确的切目录要求，由框架原地更新当前主聊天目录、保留原生上下文和会话设置并在原聊天回执；未支持此行为的后端明确拒绝，不创建空白上下文；任务和独立子会话同样可在空闲、无排队输入且适配器支持时修改自身目录。不能只改一段提示词假装 cwd 已改变。

## 研究群话题总控

研究群默认支持主会话统筹、独立话题研究与成果摘要回传，无需开关；`group-mode auto` 只设置主聊天及话题免 @ 输入，需飞书群全量消息权限生效。阶段进度仅保留子话题；整个话题目标完成后才自动回传最终交付。也可在子话题明确说“向主会话汇报当前进度”，或用 `/tab topic-report <摘要>` 主动汇报，汇报不等于话题完成。`/tab topic-report` 查看最近报告，`send` 明确回传，`final <最终摘要>` 明确确认整体完成。`/tab topics` 查看关联话题、`resume` 恢复停止后的待回传工作。关闭或空闲不表示话题完成。已有话题不强行重建，任务树保持独立。见[BOT 与群聊管理](bot-management.md#群主会话总控与独立话题)。

### 主会话的子话题总览

群主会话可直接说“总结一下我们当前有几个子会话，分别负责啥”。这是本 BOT、本群、当前用户与本主会话关联话题的只读总控能力，不要求 Manager 角色；全局会话列表仍只在 Manager BOT 单聊开放。主会话每轮接收最新数量、分工目标、运行状态和各话题已提交的报告摘要；未提交最终总结的明确标注，历史报告和关闭状态不当成完成。各子话题的完整讨论及本地阶段进度保持独立。

明确的总览短语不经过全局会话数量分类；同义查询有独立的 topic_query 意图。主会话空闲时，由原 Agent 在原上下文中据索引汇总；运行中、关闭或等待初始化时，返回只读话题卡片，不打断任务或恢复会话。`/tab topics` 也会列出数量、目标与已提交摘要。索引不再仅给前十个子话题附带摘要；内容按长度上限展示。新建空话题尚无明确目标时显示“尚未指定目标”，有首次用户任务后用该任务作为目标依据。
