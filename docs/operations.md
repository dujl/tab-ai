# 运行、升级、备份与排障

## 无图形服务器

Agent 作为后台子进程运行，不要求 TUI 或显示器。服务可以交给 systemd、launchd 等进程管理器；tmux 只是可选运维工具，不承担原生 session 持久化职责。

```bash
tab-ai serve
```

远程使用 Dashboard：

```bash
ssh -L 4317:127.0.0.1:4317 user@server
```

在服务器执行 `tab-ai dashboard`，然后在本机浏览器打开其 localhost 链接。令牌来自服务器数据目录；端口冲突时调整 SSH 本地转发端口并使用对应地址。不要直接开放管理端口到公网。

## 正常停止和升级

1. 用 Dashboard 查看运行中 session 与待处理审批，等待任务结束或明确暂停。
2. 对服务主进程发送 SIGTERM，或在前台按 Ctrl-C。
3. 备份配置、数据与原生 Agent 数据。
4. 更新依赖并执行 `npm run check`、`npm test`、`npm run build`。
5. 启动同一配置对应的服务；确认 BOT 数、会话 ID、原生 ID 和工作目录没有变化。

`dataDir/daemon.lock` 防止同一数据目录重复启动。不要在进程仍运行时盲目删除锁文件。运行中的任务在重启后不会自动重放；需要检查错误/中断状态后继续。

修改源码本身不会更新已运行服务。网页静态文件和后端代码都需要重新 build，后端需要重启。开发预览可与生产使用不同端口、独立数据目录，避免接入相同 BOT 两次消费消息。

## 备份范围

| 数据                | 内容                                                              |
| ------------------- | ----------------------------------------------------------------- |
| 配置文件            | 渠道引用、目录别名、默认 Agent、角色、群模式                      |
| 数据目录            | SQLite、任务队列、会话卡片、附件、向导草稿、访问 token 与渠道凭证 |
| 原生 Agent 用户目录 | 原生登录、会话历史和原生配置；路径由各 Agent 决定                 |
| Workspace           | 实际代码、文档和生成产物                                          |

停止服务后复制 SQLite 最简单。在线备份要使用 SQLite 备份机制，不能只复制主文件而忽略 WAL。`credentials.json` 是文件权限保护，不是加密保险库。备份中含登录与管理能力，应采用相应的访问保护。

## 常见问题

### 发送消息没有反应

依次检查：后台是否运行；消息是否发给正确 BOT；用户是否在此 BOT 授权名单；群模式是否需要 @；平台是否投递了消息；模型登录/额度是否有效；当前会话是否关闭、在终端中或等待初始化。`tab-ai doctor` 检查 CLI/凭证可读性，不代替真实平台收发验收。

### 说了新建会话，但 Agent 没开始

普通独立会话可能已创建，卡片在等目录和附加指令。查看新话题标题、管理 ID 与首个任务等待项，点击“使用当前设置直接开始任务”或 `/tab begin`。原生 ID 尚未启动不是创建失败。

独立交互节点和编排节点都在同一任务目录中。`/tab new` 不自动启动调度，`/tab task` 创建可自动拆分的主任务。

### 子任务一直排队

查看并发是否已满、依赖是否验收完成且对应版本报告就绪、父/祖先任务是否暂停或阻塞、session 是否已关闭或交给终端。取消某个依赖不等于完成它。自动轮次达到 40 的任务需要检查范围，不应无止境循环。

### 子任务说做完了，但主任务没有结果

检查是否调用 `task_report`，任务是否进入待验收。普通结束文本不是完成报告。结果会等源子轮结束、父任务可调度后投递；父任务运行时结果排队。报告仅发送成果包，不复制子任务原始工具日志。

### 审批卡片“已结束或服务重启”

请求可能已超时、处理完、取消或因重启失效。检查当前 session 的 `/tab pending`，不要重复点击旧卡片假设批准成功。需要继续任务时让 Agent 核验已有操作再执行。

### 附件无法下载

检查应用实际权限、文件访问范围与消息资源是否仍存在。登记附件、读取群消息、下载资源可能需要不同平台权限。按需用 `/tab files download`；向导中的用户授权不自动补齐机器人应用权限。

### 看不到新界面或更名后列表为空

确认正在运行的是新 build，浏览器刷新后连接的端口和数据目录正确。确认配置指向预期的 `dataDir`（默认 `~/.tab-ai/data`）。详见[安装与升级](configuration.md)。

### 群里其他成员不能审批

当前请求仍绑定原发起人，公开话题不代表多人共享审批权限。Manager BOT 的全局管理权限和原生请求的答复权限是不同检查。

## 验证层次

`npm test` 使用隔离临时目录验证状态机、路由、API、权限和原生协议适配。浏览器检查覆盖任务树和网页操作。真实 Agent / 真实聊天平台的联调需要有效登录、额度和平台权限；模拟测试通过不等于所有真实平台都已验收。

仓库的 `scripts/eval-task-orchestration.mjs` 使用实际 Codex Provider 在独立本地数据目录执行任务，会消耗额度并留下原生会话记录，但不向平台发送消息。其他 provider 应分别做端到端验收。

### 同一局域网访问 Dashboard

推荐设置配置的 `dashboardLanHost` 并在空闲时重启，由主服务提供入口。主服务保持默认回环监听时，也可单独启动代理入口（将示例 IP 替换为本机实际的内网 IPv4）：

```sh
node scripts/dashboard-lan.mjs 192.168.1.10
```

入口与主服务使用同一个端口（默认 4317，可用第二个参数指定）。访问 `http://192.168.1.10:4317`，使用原 Dashboard 访问令牌登录。也可将 `tab-ai dashboard` 输出链接中的 `127.0.0.1` 替换成该 IP，保留其余内容。令牌拥有管理权限，不应公开转发。

入口仅绑定指定的本机私网地址，校验 Host/Origin，并保留后端令牌校验；不会代用户填入令牌。只适用于可信局域网的 HTTP 访问，不是公网地址。跨网络使用 SSH 转发或有 HTTPS 和访问控制的网关。独立入口停止或机器重启后需要重新启动，IP 变化时也需要更新地址。

## 统一任务回填与管理路由降级

先停止服务并预览 `tab-ai migrate-tasks`，确认计划后运行 `tab-ai migrate-tasks --apply`。写入全过程持有实例锁；自动生成权限 0600 的 SQLite 备份，事务检查备份期间数据未变化。保存 Session/nativeId、绑定、历史、既有编排成果，历史节点只登记不自动执行。再次执行无变化时不重复回填。

语义管理判断暂不可用时，普通工作消息继续送到当前原生会话，明确的附件处理要求进入既有附件流程；涉及切换目录/模型、开关话题等管理动作时提示使用 `/tab` 明确命令。判断等待最多 10 秒，连续服务故障进入 30 秒冷却，不对普通消息重复输出“未执行”。校验不合法的管理决定仍禁止执行；关闭、绑定变更不会触发重定向到其他会话。`routing_degraded` 事件用于排查，不记录供应商密钥或完整报错。
