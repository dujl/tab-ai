# 本会话审批策略与临时授权

## 两层控制

审批策略决定原生 Agent 何时询问；每次审批的决定则指定本次允许、按原生范围在本会话允许、拒绝或取消。沙箱配置是另一层控制。本功能不修改全局、用户或项目的权限配置，不启用绕过沙箱，也不把授权共享给主任务、子任务或其他 session。

**Codex 框架默认使用 `on-request`（按需审批）。** 未单独设置策略的新会话和既有会话均在下一次执行时显式传入该策略；已有 `untrusted`、`never` 等独立选择保持原值。选择 `native` 则在当前 Session 保存明确的原生配置选择，不传入框架默认策略。显式选择与默认值来源分别保存，不改动原生会话 ID。

默认值统一应用于 `thread/start`、`thread/resume`、独立维护操作的恢复及原生终端交接命令；不修改沙箱。运行中的轮次不被中途改写。Claude Code 和 OpenCode 仍沿用各自原生默认。新子任务、普通会话重置仍不继承父会话的临时授权或独立策略，未设置时使用本 Agent 的框架默认。

同一任务的 Dashboard **审批与执行 → 审批策略 / 清除授权** 可设置和撤销；聊天中用 `/tab approval` 打开本会话卡片。`/tab approval clear` 清除临时授权但保留所选策略。修改策略、清除授权必须在当前轮结束且已退出原生终端时进行；网页校验目标与状态版本，旧面板不能改动新状态。

Dashboard 对话工具栏也直接提供 **审批策略**；飞书首页的 **审批与执行** 分组提供该入口（企微从更多本会话进入）。策略选择页面显示每项的具体行为，选择 `never` 时明确说明它不会扩大权限，也不是“允许所有”。没有用户选择时仍沿用原策略，不因审批频繁而自动扩大授权。

每次审批展示实际可用的决定及说明：本次允许只处理当前请求；会话内允许仅复用原生请求的授权范围，不等于允许所有工具。原生未提供会话内决定时明确提示不能扩大授权。Codex `thread/start` / `thread/resume` 返回的有效 `approvalPolicy` 优先用于该轮卡片说明，保留运行实例时同时保留此策略快照；原生未返回时仅说明本会话设置或沿用原生配置，不猜测实际生效值。原生分类策略显示已知类别的可询问／不询问并拒绝状态，不把未知字段原样展示或擅自转成全允许。

策略与选项说明随 `interaction` 事件保存；飞书卡片、企微卡片、文字命令和网页都展示授权范围。网页不依赖鼠标悬停才能阅读选项说明，移动端也可直接看到。审批卡片不是修改策略的入口，调整策略仍需先结束当前轮。

| Agent       | 本会话策略                            | 单次审批                                                                            |
| ----------- | ------------------------------------- | ----------------------------------------------------------------------------------- |
| Codex       | native、untrusted、on-request、never  | 根据 `availableDecisions` 提供 accept、acceptForSession、decline、cancel 的对应选项 |
| Claude Code | native、default、acceptEdits、dontAsk | 本次允许；原生提供完整可支持的 allow 规则建议时提供本会话允许；拒绝/取消            |
| OpenCode    | 沿用原生配置                          | 本次允许、相同请求范围在本会话允许、拒绝                                            |

`never/dontAsk` 表示不弹审批、权限不足时不批准，不等于全权限。`untrusted` 仍由 Codex 判断可信命令，不把它标作“所有工具每次必问”。不支持的策略或选项明确拒绝。保持 `native` 时不添加覆盖参数。

Codex CLI 0.163.0 的协议列出 `untrusted`、`on-request`、`never` 和分类策略。官方配置文档对 `untrusted` 的支持说明可能不同，部署到其他版本时需要核对其原生协议；框架不会静默将被原生拒绝的策略替换成其他权限模式。持久命令／网络规则修订可能超出单个 Session 的作用域，当前不将其包装成“允许所有”或会话内授权。

显式策略保存在当前 Session 的 `approvalPolicy`，可以在同一会话重启后继续使用；重置得到的新 session 和新子任务不继承独立策略，Codex 使用默认 `on-request`。未设置字段不需要批量改写数据库。清除临时授权保留策略字段及默认／显式选择。临时授权保存在运行实例内存中，关闭、重置、服务重启、显式清除后失效；原历史、nativeId、已发生的审批记录均保留。

## 各原生适配器的边界

**Codex**：保留 `availableDecisions` 的限制，回传原生决定，不用本地命令相似度推断许可。仅当用户选择会话内授权时，保留该 tab-ai session 专属的 app-server；后续消息在同一进程、同一原生 thread 中发起新 turn。其他 session 使用独立进程。失败或中止后销毁该实例，不自动重播操作；目录、模型、策略或指令发生变化时按新配置恢复同一 thread 并重新审批。压缩与原生终端交接也会清除保留实例。

最多保留 8 个空闲授权实例，超过后回收最早空闲的实例，并在原会话活动记录中写明临时授权失效；不会回收正在执行的实例。被回收后的下一轮仍恢复同一 nativeId，只是需要重新确认权限。空闲实例收到意外的工作轮或工具请求时终止，不批准无人监管的操作。

**Claude Code**：只接入原生完整的 `addRules + allow` 建议，目的地强制为 `session`；不接受以此按钮修改模式、移除拒绝规则或写入 settings 文件。后续轮次将同一 session 已授予的规则通过 SDK `allowedTools` 重加，由原生权限引擎匹配。若请求仍进入回调（例如强制询问、组织要求），继续询问用户，不用框架缓存跳过。没有可适配规则时只提供本次允许。

**OpenCode**：不同版本的原生 `always` 可能保存项目规则。本框架不回传 `always`，而将权限类型与完整 patterns 集合保存在当前 tab-ai session 的内存中；相同请求范围再次出现时回传 `once`。不做命令前缀或通配符的自行扩大匹配，不写入项目授权。复用会在原会话活动记录中说明。

## 交互与审计

审批答案使用 `{allow:true/false}`，也可按请求支持范围提交 `{allow:true,scope:"session"}` 或 `{allow:false,cancel:true}`。服务端和卡片注册表都检查此请求实际提供的选项，不能凭手写 scope 获得更大的授权。

飞书、企微与 Dashboard 按实际选项展示按钮；文字渠道的 `/tab pending` 列出 `/tab approve <ID> allow|session|deny|cancel` 中本次可用的命令。请求仍绑定原会话/发起人和截止时间，旧卡片、重复提交和超时均不能批准。

审批 `decision` 保存明确范围，`interaction_closed` 保存终态及范围，Dashboard 展开时显示。绿色的“已允许”只代表当时授权成功，不表示工具已成功或授权现在仍有效。具体执行结果仍看工具记录。详见 [审批与执行记录](execution-records.md)。

## 上下文与模型缓存

默认未授予会话内授权时，Codex 仍采用每轮启动 app-server、用相同 nativeId 调用 `thread/resume` 的方式。恢复原生历史与保持同一个本机进程不是同一件事；进程退出不会自动清空持久对话历史。

模型的 prompt cache 由实际提供方管理，命中取决于模型、前缀、工具/指令结构和缓存有效期等。进程重启不等于缓存必然丢失，保留进程也不保证缓存命中。框架不改写提供方的缓存配置，不凭 nativeId 推定缓存率。

Codex 的 `thread/tokenUsage/updated` 上报会追加为 `usage` 事件；Dashboard 审批与执行页显示最近上报的输入、缓存输入和输出 token 数。无上报时明确显示未知，不编造 0 或命中率。统计为原生提供方报告，历史是否恢复另用跨轮内容验证。

参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server#approvals)、[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Claude SDK 权限](https://code.claude.com/docs/en/agent-sdk/permissions)。

## 跨入口卡片状态同步

网页、飞书按钮及文字命令均通过同一个 `Manager.answer` 完成决定；决定生效后立即失效原卡片的服务端操作入口，再异步将原飞书卡片替换为终态。终态更新失败不会再次提交审批或重放工具。

飞书原卡片替换对网络超时、连接故障、HTTP 429/5xx 和飞书频控 99991400 最多尝试三次（首次失败后等待 500ms，再失败等待 1500ms），每次使用同一消息 ID 和同一终态内容。权限、参数和月度额度错误不盲目重试；参见 [飞书通用错误码](https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code)。更新成功记录 `interaction_card_synced`；最终失败记录带审批 ID 的 `delivery_error`，仅保留安全的错误码与尝试次数，不记录凭证、请求头或原始响应。除已有独立超时通知的情况外，在原审批话题提示已记录的结果及卡片显示未同步，避免把旧按钮误认为仍待操作。
