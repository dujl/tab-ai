# 主任务与子任务编排

## 1. 何时使用任务树

任务可直接对话，也可启用编排。树形编排适合目标可拆分、需要独立执行和集中验收的工作。例如“行情系统设计”拆为接入、存储、订阅，再把接入拆为重连与补数。

```text
主聊天（仅提供入口）
└─ D：行情系统设计 / 独立 session
   ├─ D1：数据接入 / 独立 session
   │  └─ D1.1：断线重连 / 独立 session
   └─ D2：存储与订阅 / 独立 session
```

飞书里这些是同一聊天中的同级话题，不是平台原生嵌套话题；父子关系由 tab-ai 保存，并在卡片与 Dashboard 中展示。微信、企微、钉钉没有等价话题界面时使用虚拟子会话路由。

## 2. 创建入口

聊天命令：

```text
/tab task 设计行情系统，拆分接入、存储和订阅三个子任务，完成后验收汇总
```

自然语言：

```text
新建一个主任务，设计行情系统，自动拆成独立子任务执行并汇总。
```

或者在 Dashboard 的 Tasks 中“新建任务”。`/tab new` 创建独立交互节点，`/tab task` 创建自动编排主任务；界面不按这项内部能力划分任务类型。

主任务只接收本次明确给出的目标，不复制主聊天历史。若目标只说“刚才那个方案”，应补全任务说明；分类器不会自动把整段旧聊天转给新任务。

聊天 `/tab task` 会立即排队执行；Dashboard 新建默认等待输入，勾选“创建后立即执行”才执行。需要指定目录时在自然语言中明确给出，或使用 Dashboard 的目录字段。任务模式目前不提供自然语言内设置系统角色的入口；可使用实例默认附加指令。

## 3. 自动拆分与手工追加

主 Agent 通过 `task_create` 提供子任务标题、目标、验收标准和必要资料。框架负责创建话题、session、任务记录和队列。子任务也有同样的工具，可以继续拆分。

在 D 话题补充：

```text
给当前任务再增加一个子任务，设计断线重连和补数机制，完成后由你验收。
```

当前任务身份会提供给独立意图识别器，这类请求交给 D；明确另起独立主任务时才新建另一棵树。也可以绕过识别，定向发送：

```text
/tab task-to <D的任务短ID> 请新增一个独立子任务，完成压力测试方案。
```

Dashboard 可直接选中父节点后“新增子任务”。这会调用同一后端服务，不要求 Agent 先生成拆分计划。

## 4. 用户在哪里输入

| 输入位置                         | 接收方                             |
| -------------------------------- | ---------------------------------- |
| D 的飞书话题                     | D 的 Agent                         |
| D1 的飞书话题                    | D1 的 Agent                        |
| `/tab task-to <任务短ID> 内容`   | 指定任务 session，不切换主聊天绑定 |
| Dashboard 选中任务的“对话”输入框 | 当前选中任务                       |
| 主聊天普通消息                   | 原主聊天 session，不自动广播给任务 |

任务正在运行时，补充消息持久化排队；没有广播给所有子任务。跨子任务协调应在主任务提出，由父 Agent 决定分工或验收要求。

## 5. Workspace 与上下文

新子任务默认继承直接父级工作目录，不自动创建目录、分支或 worktree。空闲节点可按适配器能力明确修改自身目录；已有子节点不随父级迁移，后续新节点继承创建时的直接父级目录。

共享的是磁盘文件，不是原生对话历史。D1 不自动获得 D 或 D2 的聊天内容；父任务只给子任务明确的任务简报，子任务通过结构化结果回报。

文件操作仍受原生 Agent 权限约束。当前没有自动文件锁、合并冲突解决或操作系统级租户沙箱。并行编程应划分文件范围，或设置同级依赖让冲突工作串行执行。

## 6. 工具与结果回传

| 工具               | 作用                 | 范围                     |
| ------------------ | -------------------- | ------------------------ |
| `task_list`        | 查询任务状态与结果   | 自己和直接子任务         |
| `task_create`      | 新建子任务           | 当前任务下面             |
| `task_progress`    | 保存阶段进展，不结项 | 自己的任务               |
| `task_report`      | 提交成果包           | 自己的任务               |
| `task_review`      | 指定版本验收/返工    | 直接子任务               |
| `task_report_read` | 读取版本化交付报告   | 本任务、下级或已声明依赖 |
| `task_experience`  | 检索有来源的经验     | 同一授权聊天与用户范围   |
| `task_cancel`      | 取消不再需要的工作   | 直接子任务及其后代       |

结果结构：

```json
{
  "summary": "完成了什么、关键结论是什么",
  "artifacts": ["产物路径或交付说明"],
  "checks": ["执行过的验证与结果"],
  "issues": ["遗留问题，没有则空数组"]
}
```

一轮结束、普通文字回复或生成文件不等于任务完成。必须显式报告。子任务报告后进入“待父任务验收”；框架把结果包排到父 session，等子轮结束、父任务空闲和并发容量可用后投递。

父任务验收调用带 `revision` 的 `task_review`。接受后子任务完成；拒绝必须给出具体反馈，子任务复用同一个原生 session 返工。过时报告版本不能再次验收。父任务需先处理全部编排子任务，才能报告最终结果；未加入调度的历史交互节点不阻塞验收。新增工作会使相关祖先已有成果与 revision 失效，历史报告保留。

## 7. 依赖与限制

子任务创建时可指定已存在的同级任务 ID 作为依赖；待依赖验收通过后才执行，并获得依赖的结果包。不能依赖另一个任务树或未来尚未创建的任务。

- 每棵树最多 32 个节点，包含根节点。
- 每个节点最多 12 个直接子任务。
- 根节点下最多八层子任务。
- 每个任务最多自动执行 40 轮，当前是累计计数；普通 resume 不重置该计数，也不是 token 预算。
- 并发受实例的 `maxConcurrentRuns` 控制。

取消依赖不会自动当成依赖成功。排队节点若长期无法推进，应检查其依赖与祖先状态。

## 8. 状态与恢复

| 状态          | 含义                      | 常用下一步                 |
| ------------- | ------------------------- | -------------------------- |
| 创建中        | 远端话题/session 正在建立 | 等待；未知投递不盲目重试   |
| 排队          | 已有输入，等容量或依赖    | 检查并发与前置任务         |
| 执行中        | 原生 Agent 正在运行       | 等待、补充或暂停           |
| 等待结果/补充 | 一轮结束，但未最终完成    | 等子任务回报或用户补充     |
| 待父任务验收  | 已有成果包                | 父任务核验并接受/返工      |
| 已完成        | 显式报告且子任务已处理    | 可追加新工作，重新进入处理 |
| 需处理        | 中断、失败或达到上限      | 查看错误，再决定继续       |
| 已暂停        | 停止该子树调度            | 恢复祖先后再继续           |
| 已取消        | 明确终止                  | 保留历史，新工作建新任务   |

`/tab task-pause`、`/tab task-resume`、`/tab task-cancel` 在任务话题操作当前节点，也可传任务 ID。关闭任务 session 会暂停任务；打开 session 与恢复任务调度是两个步骤。

服务重启保留树、队列和原生 ID。未执行队列可以继续；执行中的轮次被标为中断，需用户继续，不自动重做可能已生效的工具操作。原生审批等待不能假装跨进程恢复，旧卡片失效时应检查最新状态。

## 9. 群聊和权限

飞书群可用相同方式创建任务；是否需要 @ 由本群模式决定。所有节点留在原群，结果仍回到父任务 session。不同群、BOT、用户不能通过伪造任务 ID 越权访问。

子任务的原生问题与审批集中发到根任务话题，注明子任务名称；答案仍回到实际原请求。默认只有原发起人能回答。群成员看到公开话题不等于取得审批权限。任务“父节点”不是 Manager BOT，也不因此获得全局管理权限。

## 10. 会话与任务树的展示关系

每个成功建立的任务节点绑定一个独立 Session，但任务状态与会话执行状态不同。完成任务不会自动关闭会话；空闲会话也不表示任务已完成。Dashboard 已提供统一任务目录、分层导航、大纲和分支聚焦，见 [Dashboard](dashboard.md) 与 [树形投影](session-tree-design.md)。

## 交付报告接续

`task_report` 可携带结构化 `handoff`（产物、规格、验证、遗留、经验）。框架为成果 revision 整理报告；依赖必须已验收且对应报告可用，下游才能开始，并在 TaskJob 固定所使用的报告版本。关闭 Session 也会整理结束报告，但不代替任务验收。完整格式、恢复与降级说明见 [交付报告与可复用经验](session-reports.md)。
