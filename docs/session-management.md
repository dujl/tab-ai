# 会话控制与卡片

用户步骤见 [会话手册](sessions-guide.md)，网页见 [Dashboard](dashboard.md)，通道菜单见 [管理菜单](management-cards.md)。本页说明控制行为与真实执行的对应关系。

## 状态卡片与管理菜单

飞书 Session 可维护一张持久状态卡，发送到它自己的主聊天或话题，并随公开生命周期更新。卡片身份和状态存库，回调检查发起人、原聊天、消息和版本。初始化使用独立表单，执行后的卡片与管理首页复用同一信息来源和操作顺序；结果未知的投递不自动重复创建。

`/tab menu` 与 `/tab card` 均主动打开同一“会话信息 + 会话管理”面板，卡片附项目 GitHub 入口。飞书菜单导航优先原地更新，手动编辑面板不被后台状态刷新覆盖；`/tab admin` 是独立的全局管理中心，仅 Manager Bot 已授权单聊提供。企微普通工作和附件澄清不自动附带这类菜单。审批、提问和工具进度则按原生事件展示，不属于主动管理菜单。

## 身份与路由

管理 ID 与 nativeId 是不同标识。首次启动原生工作前可没有 nativeId；开始后持久保存，状态卡、`/tab status`、`/tab main` 和网页可查询。`/tab main` 只查询本 Bot、聊天和用户绑定的主会话，不创建、恢复或改绑。

群主会话的下级数量/分工查询只读本分支，无需 Manager；全局列表与跨 Session 管理仍受独立授权限制。查询关闭节点不会自动打开它。

新独立节点挂到明确的直接父级；飞书平台话题是平级入口，逻辑关系保存在框架。其他通道使用已实现的引用/定向路由，未知引用要求明确指定，不猜测投到主会话。

## 初始化、模型和附加指令

初始化卡片显示 Session 保存的实际目录和附加指令；目录留空保留当前值。首个任务单独保存为 pendingInitialTask，明确开始后才执行，不因保存表单就丢失或重复任务。

模型/思考选项从该 Agent 实际能力读取；按 Session 及设置 revision 保存，取消草稿不改原值。运行、审批或维护期间不允许覆盖设置，下一轮生效，不向工作 Agent 伪造用户输入。

有效背景组合原生指令、可信平台背景和显式会话附加指令。飞书、企微、钉钉的默认在线文档平台来自当前通道；个人微信无法单独确定文档平台时询问用户。`/tab instructions` 查看公开通道背景及用户附加指令，不公开原生私有配置或凭据。

## 工作目录

新子任务默认继承直接父级目录，显式允许的创建参数可指定目录；创建后改父级不会追改已有子节点。Bot 默认目录只作用于未来新节点。

`/tab workspace` 查询当前目录；`/tab workspace <目录或别名>` 或网页“切换工作目录”修改当前节点。路径带空格可包引号，必须已存在。

框架校验当前绑定、授权、空闲、无排队输入/下载及非终端占用。已有历史要求适配器声明保留上下文迁移能力；Codex/OpenCode 已接入，Claude 尚未开放该迁移。成功后保留 Session/nativeId、模型、附加指令和历史，下一轮使用新 cwd；不执行一条 Agent 的 cd 指令来冒充切换，不通知其他单聊。关闭节点改目录后仍关闭。

API 为 `POST /api/sessions/:id/replace-workspace`，仅修改所选当前绑定节点。网页对话正文用于工作请求，不执行聊天管理路由，应使用工具栏或 API。目录迁移不等于文件白名单沙箱。

## 停止、关闭与重置

| 操作    | 行为                                                                                   |
| ------- | -------------------------------------------------------------------------------------- |
| stop    | 中断当前工作/压缩轮，保留历史；不等于取消未来循环                                      |
| close   | 关闭本 Session、撤销交互并保留 nativeId；编排任务暂停调度，异步生成结束报告            |
| open    | 打开同一 Session 等待新输入，不重放历史；调度暂停需显式恢复                            |
| reset   | 明确确认后重置原生上下文；编排节点保留 Task/Session，交互节点归档原 Session 并接续关系 |
| compact | 调用原生总结，保持同一 nativeId，较早细节可能省略；框架历史不删除                      |

重置校验 revision、当前占用和排队输入；旧原生 ID 保存在 context_reset 或归档记录，不作为任务取消或验收通过。压缩按 accepted/running/completed/noop/failed/unconfirmed 展示，受理不等于完成。关闭或空闲不表示目标已完成。

结束报告与有来源的经验可在 `/tab report` 或网页“交付与经验”查看，详见 [交付报告](session-reports.md)。

## 原生终端与持续执行

`tab-ai native <管理ID>` 或 `/tab detach` 释放桥接后返回原生 command/cwd；退出原生 CLI 后 `/tab attach` 交回，避免两边同时写同一个上下文。使用原生 ID 直接恢复 CLI 与打开框架 Session 是不同动作。

Codex/Claude 的原生交接携带已组合指令；Codex 未获取原生指令快照时需先在框架继续一轮。OpenCode 带逐轮 system 背景的 Session 没有等价终端参数，会明确提示继续在框架使用。

`/tab loops` 仅枚举已接通的框架调度和 Codex goal；停止所选项须确认取消来源，不把中断一轮当成取消周期任务。未接入的原生 Cron/插件循环在原生入口管理。细节见 [原生会话压缩与循环控制](management-cards.md#原生会话压缩与循环控制)。

实现：`core/manager.ts`、`core/session-controls.ts`、`core/session-settings.ts`、`channels/lark-session-card.ts`、各 Agent 适配器。

### Token 信息

会话信息将上下文占用和累计消耗分开，窗口容量由原生上报时显示占比，输入/输出/缓存与采样时间放在详情。手动压缩完成后显示同次操作前后变化；缺少一端时明确待更新，不虚构压缩率。统计按原生会话隔离，旧上下文失效、原生重置和中止都不会继续展示旧值为当前占用。各 Agent 的采集能力与口径见 [管理卡片](management-cards.md#token-用量与压缩对比)。
