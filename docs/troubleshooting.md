# 故障排查

先确认运行的是预期安装版本与配置：

```sh
tab-ai --version
tab-ai --help
tab-ai doctor
```

自定义实例应每次带相同 `-c /path/to/config.json`；日志来自自己启动的前台终端或服务管理器。报告问题时提供版本、操作步骤和脱敏错误，不上传真实数据库、登录链接或完整凭证。

| 现象                             | 先检查什么                                             | 处理方式                                                        |
| -------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------- |
| 找不到 tab-ai                    | npm 安装前缀的 bin 是否在 PATH                         | 源码可先用 npm start --；包安装检查 npm prefix -g               |
| Node/SQLite 导入失败             | Node 是否至少 22.16，运行服务和终端是否使用同一 Node   | 修正服务管理器的 PATH，使用已验证版本                           |
| 端口占用或实例锁                 | 是否已有服务使用该配置/端口                            | 复用已有服务；开发改用独立 dataDir 和 port，不盲删活动锁        |
| 网页无法连接                     | serve 是否运行，是否在另一台机器使用了自己的 127.0.0.1 | 同机用 dashboard 链接；远程使用 SSH 转发或显式局域网配置        |
| 网页提示未授权                   | 是否使用同一数据目录生成的有效 token                   | 重新执行 tab-ai dashboard，避免转发完整链接                     |
| 模型执行失败                     | 原生 Agent 命令、同用户登录、Provider、额度及网络      | 先在隔离目录验证原生客户端；tab-ai 的 Bot 登录不能代替模型登录  |
| 群内消息无响应                   | 是否 @、Bot 可用范围、事件订阅与消息权限               | 检查 group-mode；auto 配置不能绕过平台未投递的消息              |
| 看不到全局管理菜单               | 是否 Manager Bot 的已授权单聊                          | 本会话使用 /tab menu；群分支查询使用 /tab topics 或任务树       |
| 审批后没有继续                   | 请求是否已过期/中止，原生进程是否报错                  | 查看审批终态与工具记录；不要反复点旧卡或把允许当作执行成功      |
| 旧菜单按钮失效                   | 卡片是否超过有效期、服务重启或会话绑定已改变           | 在目标聊天重新发送 /tab menu；不跨聊天沿用旧操作                |
| 附件仍未下载                     | 平台是否投递元数据，是否明确提出处理附件               | 指定文件名/引用；候选列表出现时选择编号；没有附件就补充明确来源 |
| Token 显示未上报                 | 原生是否存在当前 ID 对应的有效统计                     | Codex 会只读补查历史；看采样时间，缺失不代表零消耗              |
| 压缩停止后数值不确定             | 是否收到原生完成标记和新的 token 采样                  | 查看压缩操作记录；停止不是撤销，不自动重试副作用                |
| 子任务目录不正确                 | 创建时的直接父级目录、是否显式覆盖                     | 初始化卡片核对当前保存值；改父级不会追改已存在子节点            |
| 子任务空闲但父任务未收到完成总结 | 是否已提交最终交付或明确要求汇报                       | 阶段进展留在子节点；空闲或关闭不自动等于目标完成                |

## 恢复执行结果

发送失败时，框架可能已保存结果，可先使用 `/tab last` 或网页历史查看。不要立即重新发送可能写文件、上传或发布的原任务，以免重复副作用。框架收到的受理、工具获准、工具成功和任务验收是不同阶段。

## 安全提供诊断材料

保留时间、框架管理 ID 的必要片段、所选 Agent、通道类型和可复现步骤。原生错误有时包含网址、Header 或命令参数；先脱敏再公开。需要私下报告漏洞时使用 [安全说明](../SECURITY.md) 中的联系方式。

数据恢复和空闲部署见 [维护](operations.md)，用量口径见 [管理卡片](management-cards.md#token-用量与压缩对比)，三类 ID 与目录规则见 [会话手册](sessions-guide.md)。
