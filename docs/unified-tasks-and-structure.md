# 统一任务概念与主区结构视图

本页描述 Dashboard 的任务模型和主区导航。Tasks、Agents、Bots 分别提供入口，总览汇总运行状态。

## 任务与执行上下文

用户通过 Bot 使用 Agent 处理一个任务。任务有自己的对话、目标、进展与成果；可以独立执行，也可以拆出子任务，子任务继续分解。父子关系表达工作分工，叶子与父节点都属于任务。叶子任务一样可以有明确目标和验收标准；有子任务的父任务也需要自己的整体交付。

产品界面使用统一的“任务”入口和树形目录。每个节点统一提供对话、任务结构、成果与设置；统一目录以稳定 key / parentKey 表示层级，映射 Task.parentId 和 Session 父级，入口统一为新建任务 / 新增子任务。Agent 选择谁执行，Bot 表示从哪里进入及结果投递到哪里，不决定任务类型。

Session 是任务的原生执行上下文，保存 nativeId、目录、模型、审批与历史。Task 生命周期与原生执行状态不能混为一个字段：执行空闲、会话关闭、子任务完成，都不直接意味着父任务目标完成。产品任务由 Task 与 Session 记录共同描述。

实现采用后端 TaskCatalog 统一目录：已有 Session 与调度 Task 使用稳定映射进入同一个任务视图，目标、验收条件、执行状态、成果与能力分别规范化。目标缺失显示待明确，不新建原生 ID、不复制历史、不创建执行队列。Session 生命周期、话题报告与 Task 持久调度分别保存。根任务可直接创建；子任务接口绑定明确的直接父级。读取目录不会启动执行或调度。

## 深层树放到主区

左侧负责入口和快速切换：根任务、最近使用、搜索与待处理；不无限展开完整深树。右侧为当前任务工作区，页签为“任务结构 / 对话 / Agent 待办 / 审批与执行 / 交付与经验”，原生待办按能力显示，保留完整路径和明确的当前节点。

### 分层导航（推荐处理深树）

在主区按列展示当前分支及相邻下级：每列有足够宽度展示名称、状态、直接子任务数。同列表示同级任务，选中后查看下一级。超过可见层级时可聚焦选中节点，重新从当前分支开始展示，祖先仍保留在面包屑；返回上级/整棵树只改变浏览范围。

这种方式不会随着深度增加而把叶节点越挤越窄；宽树可在同一列内查找，深树通过路径与聚焦继续深入。手机逐级进入或堆叠显示，不缩小整棵树上的文字。

### 可折叠大纲（全局检查）

右侧主区也提供同树的大纲模式，适合检查所有分工、状态和待处理项。支持展开/折叠、搜索保留祖先、聚焦分支。它与分层导航共享选中任务，不建立另一套父子数据。

## 节点操作与范围

点击节点选择任务；“打开对话”进入该任务独立对话；“聚焦此任务”只改展示；“新增子任务”明确绑定所选节点。父任务输入不广播到后代，操作不因为左侧选中根任务就误作用于根。草稿独立保存，任务状态与审批来源可从主区进入查看。

控制操作分别作用于不同状态：暂停调度、停止当前轮、结束目标及原生上下文重置各有对应动作，不能把任务结项与会话关闭合成一个按钮。
