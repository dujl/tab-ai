# 交付报告与可复用经验

报告适用于开发、测试、部署、研究及其他任务，不要求按固定流水线拆分。

交付报告回答“本任务交付了什么、依据和验证是什么、后续如何接续”；可复用经验是报告内提炼的“在什么条件下采用什么做法、有哪些限制”。经验保留来源报告与版本，不替代具体任务的验收或交付。IM 的任务与交付菜单分别提供报告和经验入口。交付报告读取当前会话；经验检索可以参考同一 BOT、聊天和用户授权范围内其他会话的报告。

## 何时产生

- 关闭 Session：持久化报告请求，等待当前工作轮取消并保存公开输出后，再冻结记录范围、异步总结。关闭并不表示目标完成；没有已验收成果时报告标为“尚未确认完成”，列出遗留事项。重复关闭不重复建报告。
- 取消任务子树：为各节点保存幂等的“已取消”报告，等待正在取消的工作轮保存已有公开输出；不视为目标完成。
- `task_report` 提交成果：为当前任务成果版本建立报告。子任务先为“已提交，待验收”，直接父任务 `task_review` 接受后为“目标已完成”；拒绝则标记未完成，返工成果使用新版本。
- Dashboard 的“交付与经验 → 生成 / 重新总结”或 `/tab report refresh`：主动整理当前已有记录。生成报告本身不执行任务、重开会话或重新验收。

重开会话后再次关闭会生成下一版本；旧报告截断在重开前，不混入后续工作。服务重启只恢复未完成的总结队列，不恢复中断的工作副作用。已关闭会话的报告可手动生成；服务启动不会批量唤醒或总结这些会话。

## 报告内容与可信边界

每份报告具有独立 ID、Session、可选 Task ID / 成果 revision、会话内递增版本、生成触发来源和状态。正文包含：

| 内容                   | 用途                                                       |
| ---------------------- | ---------------------------------------------------------- |
| 交付概述与产物位置     | 明确实际实现、研究或交付了什么                             |
| 接续规格               | 接口、输入输出、约束、研究口径、方法与假设；资料不足时留空 |
| 验证记录               | 区分执行 Agent 已报告的检查和未验证的主张                  |
| 风险、遗留事项、下一步 | 供父任务验收或下游继续推进                                 |
| 可复用经验             | 适用条件、做法、限制和来源依据，不把猜测当经验             |

总结器读取最近最多 200 条公开记录，总文本预算 48,000 字符；工具只保留名称、状态和退出码，不采集完整工具参数或私有推理。截断会在报告中说明。可引用的经验依据限于已提供的 event ID 和真实存在的 task-result。结构校验不等于事实审计；接续 Agent 仍需核对实际文件、接口与验收标准。

执行 Agent 可在 `task_report` 的可选 `handoff` 中直接提交上述结构化信息；否则使用独立、无工具权限的原生总结轮。Codex 使用新建 ephemeral thread、read-only sandbox、关闭 MCP/工具并限制 JSON 输出；不恢复用户工作 thread。Claude 使用无工具、非持久化结构化查询。实现使用的原生协议见 [App Server 官方说明](https://learn.chatgpt.com/docs/app-server)。

总结服务不可用时仍保留已有成果和最后公开回复，标记为“已记录事实”并展示明确提示；不会推断额外经验或虚构验证通过。可稍后重新总结。报告请求先落库，运行中断后沿用原 ID / 版本恢复。

## 父任务与下游如何接续

报告就绪后，框架登记交接事件。父 Agent 每轮从持久化报告读取各关联来源的最新可用版本，不依赖最近聊天或工具事件窗口；主会话、下级和同树已声明依赖的访问关系实时校验。上下文包括来源名称、Session / Task ID、直接父级、报告 ID / 版本、完成状态、摘要、遗留事项，以及经验的适用条件、做法、限制和依据。索引总预算约 48,000 字符，优先裁剪较早报告的正文，保留来源和版本入口；完整报告通过 `task_report_read` 读取，不要求 Manager 权限。旧版本仍可按报告 ID 读取。此动作不自动启动普通聊天，也不复制完整历史。

子任务中途主动提交的总结同样对父 Agent 可见：普通话题使用 `topic_report(kind=progress)`，编排任务使用 `task_progress`，均可附 `lessons`。阶段总结与经验持久化保存，父 Agent 下一轮从话题或任务分支索引读取，包含来源、时间或版本及未完成标记。经验属于执行 Agent 的报告，接续时仍需核验。阶段更新不会自动唤醒父 Agent、提前验收或结项；正在执行的父轮次不会被中途插入新内容。普通文字回复不自动认定为结构化总结。

每次主动提交的阶段总结也保存为版本化报告，并在父 Session 登记 `handoff_received`；相同来源 key 幂等。Web 的“交付与经验 → 收到的子任务交接资料”显示来源名称与 ID、版本、真实状态和摘要，保留最近 100 条索引，不被最近 200 条工具事件窗口挤掉。登记或通知不等于 Agent 已读；只有实际进入父 Agent 某轮输入的内容，才显示在“对话”的该轮输入快照中。既有交接索引无需重发飞书卡片即可查看，不能据此补造历史模型输入。

通知摘要正文不超过 `handoffInlineLimit` 时直接显示，默认 50 个 Unicode 字符；超过时仅显示不超过该上限的核心摘要，并提供完整 Markdown 交接文档。此限制不裁剪实际提交给 Agent 的输入快照。文档从同一版本报告生成，包含总结、产物、接续规格、验证、遗留事项、下一步与可复用经验；内容源持久化于数据库，不依赖临时文件。新生成的报告先用一句简短结论开篇；既有长摘要使用首句或有省略标记的摘录。飞书在原话题发送 `.md` 附件；Web 可从交付资料或实际输入中的关联报告入口查看、下载。其他通道未实现文档附件发送时保留报告入口，用户可在 Dashboard 下载，不默认创建其他平台的在线文档。

关闭会话产生的报告就绪后，还会在原 IM 会话发送“结束报告已生成”，并在直接父会话发送“子任务交接摘要”。飞书等支持管理卡片的通道使用卡片，其他通道使用各自支持的消息形式。通知包含来源、报告版本、真实完成状态、摘要、遗留事项、经验数量和完整报告入口；父会话收到通知不自动启动 Agent，也不把未完成或已取消状态提升为完成。不会向祖先逐级广播或向其他聊天改道发送。

报告生成与通知投递分别保存状态。原会话和直接父会话各自记录待发送、发送中、已送达、结果未确认或未发送；某一处通知失败不影响报告正文或另一处通知。服务恢复继续处理尚未发送的通知，发送期间中断则标为结果未确认，不自动重试。投递前复查原绑定、父子关系和授权；过期绑定或不可用入口不改道。Dashboard 报告详情及 `/tab report` 可查看通知状态。

历史报告不会在升级后批量发送卡片，但有读取权限的父 Agent 下一轮可直接获得持久化索引。对尚未建立通知记录的结束报告，可在 Dashboard 点击“发送报告通知”，只投递该报告，不重新总结或重开工作会话。重复点击不会重复发送，已经尝试但结果未知的通知也不会被此入口自动重试。手动重新总结与普通阶段总结不会因此自动启动父会话。

编排任务的依赖必须先验收通过，并具有匹配成果 revision 的可用报告，下游才调度。调度前将所用报告 ID、版本、任务 revision 固定写入 `TaskJob.inputReports`，可追溯“测试依据的是哪一版编码交付”。首次执行附带依赖报告；多报告正文总预算 36,000 字符，过长时保留版本索引，明确要求使用 `task_report_read` 获取全文。

例如“编码 → 测试 → 上线”：测试声明依赖编码，编码提交产物、接口规格和已执行验证，由父任务验收；测试使用对应版本报告核验。上线再依赖已验收的测试报告。调研工作同样可按“资料收集 → 方法核验 → 结论汇总”使用，不内置领域专用状态机。

原生工具：`task_report_read({reportId})` 读取本任务、下级或已声明依赖的报告；`task_experience({query})` 查找授权范围内的经验。主任务只能验收直接子任务。报告可用、工作轮结束、空闲或关闭都不替代任务验收。

## 展示与存储

- Dashboard：任务详情的“交付与经验”，查看历史版本、生成状态、规格、验证、经验和来源 ID，可加载更早报告。
- IM：`/tab report` 查看最近报告；`/tab report <报告ID>` 读取指定版本（限本任务、下级或已声明依赖）；`/tab report <报告ID> document` 获取交接文档；`/tab report refresh` 主动总结；`/tab experience 关键词` 检索经验。本会话菜单“任务与交付”提供入口。各通道沿用自身支持的卡片或文字展示。
- SQLite：`state.sqlite` 的 `session_reports` 表，正文以 JSON 保存，索引覆盖 Session 版本、Task revision、待处理状态和授权 scope；不另建数据库，不清空历史。
- 经验作为版本化报告的一部分保存，检索结果携带报告 ID / 版本；目前不是向量库，也不自动修改 Agent 的全局系统提示词。

IM 读取与自动回传限制在相同平台、BOT、聊天和用户范围内；任务工具还校验祖先/已声明依赖关系。其他用户或聊天不会因经验检索获得报告。本机 Dashboard bearer token 具有实例全局管理权限，报告 API 使用同一认证边界。

## API 与实现

- `GET /api/sessions/:id/reports?before=<version>`：每页最多 20 份，按版本倒序。
- `GET /api/sessions/:id/reports/:reportId/document`：返回 `{filename, content}`，只允许读取已生成、属于本任务/下级/依赖的报告；沿用 Dashboard bearer 认证。
- `POST /api/sessions/:id/reports`：`{ "key": "可选UUID" }`，返回 202；同 Session 同 key 幂等。
- `POST /api/sessions/:id/reports/:reportId/notifications`：`{}`，为有读取权限的已就绪结束报告建立一次通知；重复请求保留原投递状态，不重新生成报告。使用 Dashboard bearer 认证并校验会话与报告范围。
- `GET /api/experiences?sessionId=<id>&q=<关键词>`：按会话授权范围检索；本机管理员省略 sessionId 可查全局。
- `/api/state.sessionReportStates`：轻量更新时间索引，正文按需加载。状态查询支持 ETag / If-None-Match，未变化返回 304。

主要实现：`core/report-model.ts`（结构与总结约束）、`core/report-store.ts`（持久化与索引）、`core/session-reports.ts`（队列与范围校验）、`core/tasks.ts`（验收、依赖与固定版本）、`agents/topic-router.ts`（受限原生生成）、`web/server.ts` / `web/public/dashboard.js`（API 和展示）。

`test/session-reports.test.ts` 覆盖关闭与重开、活动轮收尾、幂等与恢复、总结故障降级、访问边界、通用依赖流程、版本引用、分页、ETag、异步生成期间验收状态不被覆盖，以及通知路由、指定版本读取、投递未知不重试、原绑定复查和历史报告的显式单次通知。
