# 微信与企业微信

微信和企业微信是两个独立渠道。它们各自绑定用户、管理会话，不共用 Agent 上下文。均可连接 Codex、Claude Code、OpenCode，服务器不需要显示器或公网回调地址。

## 开始接入

在项目目录先执行 `npm run build`，已有服务运行时执行 `npm start -- setup`；也可执行 `npm start -- dashboard --setup` 打开网页向导。远程服务器通过 SSH 端口转发访问本地工作台，详见 [安装向导](onboarding.md)。

### 个人微信

1. 选择“微信（个人微信）”→“微信扫码登录”。
2. 手机微信扫码确认。若要求验证码，在向导填写手机显示的验证码。
3. 用刚才扫码的账号，私聊机器人发送任意文字。收到双向测试回执后，在向导确认启用。
4. 开始发送任务。测试消息不会交给 Agent；扫码者以外的账号不会获得使用权限。

凭证和未完成登录草稿保存于本地受保护文件，配置文件只保存凭证引用。尚未确认启用时，可以取消并从草稿重新开始。二维码过期需重新获取。

依据腾讯公开的 [iLink 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md) 实现，无需安装 OpenClaw，也不引入其模型配置或提示词。API 域名只接受 `ilinkai.weixin.qq.com` 及其子域。现阶段支持文字私聊；图片、语音、文件收发和微信群不在本版本范围内。登录失效会停止轮询并提示重新扫码，不自动重复发送任务。

### 企业微信

运行 `npm start -- setup`，或在网页工作台打开“接入机器人”：

1. 选择“企业微信”→“企业微信扫码创建 / 授权（推荐）”。
2. 用企业微信扫描二维码，按手机提示确认。tab-ai 自动获取 Bot ID 和 Secret，无需手工查找和复制。
3. 私聊新机器人发送“你好”等任意文字，无需 `/tab pair`。收到回执后，在向导核对账号并确认启用；测试消息不会交给 Agent。
4. 开始发送任务。已运行的服务会直接接入新机器人，无需重启。

二维码有效期约 5 分钟；手机确认与租户审批由用户完成。扫码协议沿用[企微官方 CLI](https://github.com/WecomTeam/wecom-openclaw-plugin)使用的 `work.weixin.qq.com/ai/qc/generate` 与 `query_result`，不依赖 OpenClaw 安装，也不修改原生 Agent 提示词。返回的授权链接只接受官方域名和二维码路径；凭证保存在权限 0600 的本地文件中。取得凭证后失败或取消，可在向导选择“继续未完成配置”，无需重复创建机器人。

已有机器人或租户不支持扫码时，仍可选择“已有机器人，填写凭证”：在企微创建智能机器人，选择 API 模式和长连接，再填写 Bot ID、Secret。采用[企业微信官方 Node SDK](https://github.com/WecomTeam/aibot-node-sdk) 的 WebSocket 长连接；不是群 Webhook，也不是企业自建应用的 CorpID/AgentID 接入。可用范围及平台审批要求以企微提示为准。

扫码草稿恢复后仍使用普通消息验证。当前扫码接口提供机器人凭证，未提供可用于校验的扫码者账号，因此仍需一次私聊识别账号及本地确认；不会将第一个发消息的人直接授予 Agent 权限。群消息与空消息不能完成绑定，确认前普通任务不会执行。已有凭证手工接入仍使用配对命令。

支持文字收发、原生 Agent 工具审批按钮及可表示为选项的提问卡片。开放题等不适合卡片的场景提供 `/tab answer` 文字命令。模板卡片的实际展示及点击仍需在自己的企微租户验收。

## 企微群聊近期消息补读（可选）

除长连接回调外，官方 CLI `chat messages list` 可按时间读取当前授权可见的群聊消息。若本机 CLI 已授权同一个机器人，并有目标群的消息读取权限，可以不依赖会话存档，给触发的回复补充近期未 @ 的群消息。

在对应企微 channel 中显式配置群白名单，空数组或省略表示关闭：

```json
{
  "id": "wecom-main",
  "type": "wecom",
  "botIdEnv": "TAB_AI_WECOM_BOT_ID",
  "secretEnv": "TAB_AI_WECOM_SECRET",
  "allowedUsers": ["YOUR_USERID"],
  "contextGroups": ["wr_REPLACE_WITH_GROUP_CHAT_ID"]
}
```

本机须安装可选依赖 `@wecom/cli`，使用运行服务的同一系统账号完成 `npx --no-install wecom-cli auth init`。这与长连接 Bot ID / Secret 是独立授权。每次读取前校验 CLI 的 Bot ID 与该连接相同；不同机器人、未启用的群、私聊都不补读。配置修改在空闲时重启后生效，Dashboard 的机器人卡片显示启用群数。

当前实现为**触发时按需补读，不是后台实时监听**：

- 机器人收到群内 @ 后，执行普通会话前读取近 24 小时最多 20 条群消息（最多查询四页），并标出来源成员和时间。
- 普通消息不会因补读而创建会话、执行命令或触发模型；群消息作为不可信引用资料附在当前用户请求之后，不作为授权。
- Dashboard 主动向同一群的 session 发送消息也会补读；任务 session 不引入主群讨论。
- 单条参考最多 1000 字符，较早参考可能不在窗口中。每轮读取近期窗口，不声称逐消息增量去重或绝对实时；API 结果也受企微授权范围、同步延迟与接口可见性限制。
- 图片、文件、语音、视频的历史媒体 ID 会先登记为附件；图文混排保留文字和图片引用。登记与群聊补读不自动下载，明确要求读取、识别或处理后才获取文件字节。
- CLI 过期、授权不匹配或读取失败会明确报错，不悄悄让模型假定已读全群。

## 企微附件按需下载

实时长连接已接入图片、文件、图文混排，以及用户引用的图片/文件。单独上传只登记附件，不启动模型；群内无文字附件只接收到该发送者已有的会话。用户发送“描述图片内容”“识别这张图片”等实际识别请求时，先下载并解密，再把隔离目录中的真实文件路径交给原生 Agent。仅问“收到图片了吗”、否定或延后处理均不触发下载。

已配置 `contextGroups` 的群还可通过同一机器人的官方 CLI 读取近 24 小时、最多四页 / 100 条中的历史附件元数据（独立于最多 20 条文字参考窗口）。附件元数据在意图判断前登记，明确处理要求后再读取媒体内容。范围为当前已启用群内所有可见成员的附件；CLI 的不透明用户 ID 不能直接与长连接 userid 比较，不把姓名当作身份校验。未启用的群及私聊不补读历史；不重放附件消息里的原任务。

- 引用某张图片并 @机器人提出识别要求，可明确指定图片；当前请求携带的单个附件优先于未指定的旧附件。完整文件名能唯一匹配时也可直接指定。
- “分析这个文件”“上面的附件”等单个附件指代，优先关联本次请求之前最近五条群消息中距离最近的附件消息；中间插入几条文字不影响关联，同会话的其他附件不影响明确的最近附件指代。引用/本条附件和唯一完整文件名仍优先；不选择触发请求之后上传的文件。没有历史补读上下文时，可以关联同会话最近接收、其后少于五条用户消息的实时附件。
- 找不到附件时正常询问用户上传或引用；多个候选仍不能确定时，以简短文字列出候选，请用户回复序号、完整文件名或引用目标。此时不下载、不启动工作 Agent、不发管理菜单、不当作运行错误。原处理要求在该 session 内保存最多 24 小时，回复选择后接着执行；明确“取消/不用了”清除待处理要求。新增独立会话和重置不继承该要求。
- 历史引用按账号/群、原消息时间、媒体类型、文件名及同时间同名的出现序号形成稳定来源标识；CLI 媒体 ID 刷新只更新下载凭据，同一来源只登记一次。不同上传时间或同秒同名的多次上传仍保留多条；缺少来源元数据的记录保留，不按文件名盲目合并。
- `/tab files` 可查看全部已登记附件；`/tab files download <序号>` 仅准备指定文件，之后发送处理要求。`/tab files sync` 只同步/刷新元数据，`/tab files download all` 明确下载全部；不会默认下载多份。
- 历史媒体使用官方 `message files get --media-id`；每次下载先校验 CLI Bot ID，资源引用绑定当前账号和聊天。CLI 的身份提示和安全提示不会进入模型上下文。
- 实时 URL / AES key 只在进程内短暂保存，不写入消息记录；五分钟过期或重启后可补取群历史，未启用历史补读时需重发。历史媒体也可能因平台授权或有效期而失败，失败会明确告知且不启动工作 Agent。
- 文件按会话隔离、单文件最多 25 MB、失败清理临时文件；CLI 下载使用其允许的系统临时目录，验证返回媒体身份与本地路径后复制到附件目录，避免 macOS `/var/folders` 被官方 CLI 拒绝。成功后保留本地缓存，后续指定同一登记附件可复用。

普通聊天、附件分析和异常提示不附带管理菜单卡片。用户主动发送 `/tab menu`、`/tab admin`、管理查询或点击管理操作时才显示对应管理卡片；审批卡片保留。群内 `@bot1 /tab menu`、不换行的 `@bot1/tab menu` 及不间断空格均识别为明确管理命令，普通工作文字和引用内的命令保持原样，不从中截取命令执行。

协议依据：[官方 Node SDK](https://github.com/WecomTeam/aibot-node-sdk) 的图片/文件 AES 下载协议，以及[官方 CLI](https://github.com/WecomTeam/wecom-cli) 的 `chat messages list --doc`、`message files get --doc`。真实租户的媒体可见性和下载权限需按 [验收](acceptance.md) 单独核对。

## 微信里的主会话和子会话

### 每个机器人的默认工作目录

在 `~/.tab-ai/config.json` 对应的 `channels` 条目中设置可选字段 `defaultWorkspace`，例如 `"defaultWorkspace": "<workspace>/project"`。也可填写 `workspaces` 中的别名或 `~/` 开头的绝对目录；目录须已存在且可访问。省略时继承全局默认工作区。该字段同样适用于飞书、企微、钉钉；修改配置文件后需要在任务空闲时重启服务。

机器人首次创建主会话、`/tab init` 使用该默认值；未指定目录的新子会话优先继承已有直接父级/所属主会话目录；新建请求显式指定的目录优先。已有会话仍使用原目录，其他机器人不受影响。这是工作目录配置，不是文件访问沙箱。

修改机器人默认目录不会自动迁移已有会话。本机管理 API 支持 `POST /api/sessions/<当前主会话ID>/replace-workspace`，请求体为 `{"workspace":"/绝对路径"}`，使用与工作台相同的 Bearer 认证。此操作接受当前绑定、空闲且无排队输入的节点：原地更新目录，保留会话 ID、原生上下文、模型设置和附加指令，下一轮使用新 cwd，不自动执行任务或重放历史。后端不支持保留上下文时明确拒绝，绝不悄悄创建空白会话。执行/下载/维护中、原生终端占用、有排队输入或失效绑定 ID 均拒绝。此 API 只切换该会话；机器人默认目录仍需在配置中单独保存。聊天内可明确说“把当前工作目录切到 /绝对路径”，或使用 `/tab workspace <目录或别名>`，由框架定位原聊天并回执；详见[会话工作目录切换](session-management.md#工作目录)。

微信的 iLink 接口没有飞书话题页面。本版本通过“引用回复 + 单次指定 ID”区分上下文，**不依赖隐式切换当前会话**：

- 直接发送普通文字，始终进入主会话。
- “新开一个会话，使用 OpenCode 写小说”等同义请求，创建新的独立 Agent session 并执行任务，保留主会话。
- 引用子会话的一条机器人回复后发送文字，继续对应子会话。引用仅用于管理层路由，不作为附加提示或历史注入 Agent。
- 每条回复显示 `【主会话 · 短ID】` 或 `【任务名称 · 短ID】`。不同子会话可以同时运行，回复按各自来源标记。
- `/tab list` 列出本聊天中属于你的会话。
- `/tab to <短ID> 内容` 单次发送到指定会话；`/tab to main 内容` 单次发送到主会话。管理前缀不会进入 Agent。
- `/tab use <短ID>` 在微信显示该会话的入口消息，引用它即可继续。不会把之后的无引用消息偷偷改投到子会话。
- 引用某会话发送 `/tab status`、`/tab history`、`/tab close`、`/tab open`，操作对应会话。也可 `/tab to <短ID> /tab history`。
- `/tab main` 查看主会话管理 ID、原生 Agent ID。

引用路由依赖微信回传的服务器消息 ID。保存接收/发送消息 ID 与逻辑会话的映射，随服务重启恢复；每个机器人保留最近 10,000 条映射。无法识别引用、引用过旧、平台没有返回服务器 ID 或多个引用冲突时，提示明确选择，不将任务猜测投递到主会话。可用 `/tab to` 或新生成的 `/tab use` 入口继续。实际手机端的引用格式兼容性需扫码验收。

微信仍只有一个消息流，无法原生折叠子会话。独立查看每个会话的历史、原生 ID、模型与思考深度，请在工作台选择该会话。审批、原生提问在微信使用文字命令，引用相应子会话的提示再回答；未回答不会自动批准。

## 验证范围

自动化验证：扫码/验证码状态、取消及身份限制、凭证保护、长整数消息 ID、回复凭证、游标与引用映射重启恢复、主子上下文隔离、未知引用拒绝、短 ID 归属校验、原生审批回传。真实微信扫码后的收发与引用、企微租户收发与卡片交互需使用授权账号单独验收。

### 群聊中带 @ 的附件选择

企微群继续使用 @ 机器人触发请求。等待附件选择时，`@bot1 5`、包含不换行空格的回复、`@bot1 选择第5个` 与 `@bot1 完整文件名` 可直接回答当前候选列表。若原请求已明确机器人名称（例如 `@bot1 将文件转为在线文档`），也支持平台把提及和序号紧连显示成 `@bot15`；名称未知时不会猜测机器人名称末尾数字与答案的边界。

框架仅为待选择附件解析寻址前缀，不改写传给工作 Agent 的普通原文。明确序号、完整文件名及取消直接在框架处理，不经过意图模型；序号绑定已展示的候选快照，随后新增附件不会改变其含义。已下载的目标复用缓存，不依赖额外的 CLI 历史查询；未下载的历史资源仍按原通道刷新引用后下载。

选择完成后保留原始要求，例如继续“将这个文件输出为在线文档”，不会把一条孤立的“5”作为新的 Agent 任务。跨用户、跨群、会话切换或已过期的选择不能借用其他会话的候选。无需取消群聊的 @ 触发方式。
