# 任务树投影与导航

产品界面只有一个任务目录；数据模型和布局原则见 [统一任务概念](unified-tasks-and-structure.md)，操作见 [Dashboard](dashboard.md)。本页描述已经实现的投影，不维护另一套界面方案。

## 节点身份

`core/task-catalog.ts` 将 TaskRecord 与其 Session 合成一个产品节点。只交互节点使用稳定的 `session:<id>` 导航键，编排节点使用 `task:<id>`；这些是技术标识，不是用户需要选择的工作类型。未完成回填的数据仍能由 Session 投影，读取目录不会执行工作。

`parentKey` 来自明确的任务父级、Session 父级或根任务的入口来源，不按标题猜测。相同 Session 不重复出现。创建中的任务没有 Session 时仍可查看；缺失父级或循环数据被标记为异常并保持可见，不伪造层级。

## 主区结构

- 分层导航最多显示相邻三列，同列是同级任务；深度增加时移动可见窗口。
- 大纲支持折叠、搜索保留祖先和分支聚焦，与分层导航共享选中节点。
- 面包屑、返回上级、查看整棵树改变浏览位置，不改变父子关系或执行状态。
- 手机按列堆叠，并用“切换任务”打开入口列表，避免无限缩进。
- 选中任务、聚焦分支、页签与展示模式写入 URL；对话草稿按任务区分。

左侧负责待处理、初始化、最近使用和范围筛选。顶层任务视图聚合下级待办，但点击仍打开实际需要处理的节点。

## 状态与动作

目标状态、Session 执行状态和待用户输入分别展示。取消、暂停、关闭和空闲不能合并成一种“完成”。工具审批允许与工具执行成功也分别呈现。

新增子任务固定所选直接父级，进入该节点对话只给它发送输入。聚焦不授予管理整棵树的权限。后端仍校验同一 Bot/聊天/用户、当前绑定、层级与数量。

对应实现：`core/task-catalog.ts`、`core/session-hierarchy.ts`、`web/public/dashboard.js`、`web/public/task-structure.js`。验证见 [验收](acceptance.md)。
