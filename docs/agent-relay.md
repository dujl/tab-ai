# Agent 接力与统一任务报告

同一任务由不同 Agent 接续时，Task、逻辑 Session、父子关系、工作目录及 Web/IM 入口保持不变。每次接力创建新的执行阶段；即使再次选择之前使用过的 Agent，也建立新的原生上下文，不恢复旧阶段继续执行。

例如：Codex 阶段 A → Claude Code 阶段 B → Codex 阶段 C。三个阶段分别记录自己的 nativeId。C 接收截至 B 的最新任务报告，不使用 A 的旧 nativeId。

## 使用入口

Dashboard 的任务页选择“执行阶段”，或在对话工具栏选择“Agent 接力与阶段”。选择目标 Agent、目标能力目录中的模型与思考深度，填写可选的接续要求，再生成预览。默认交接后等待新输入；勾选立即继续后，确认成功才提交接续任务。模型目录读取用于检查目标能力，不会启动业务轮次。

IM 中发送 `/tab relay`。飞书管理菜单的“更多操作”包含接力入口；其他通道通过“持续任务与终端”进入。不支持卡片的通道使用同一后台命令与文字状态。

```text
/tab relay
/tab relay choose
/tab relay prepare claude
/tab relay prepare opencode continue {"model":"目标模型ID","provider":"目标Provider"}
/tab relay confirm <阶段ID>
/tab relay confirm <阶段ID> accept-facts
/tab relay cancel <阶段ID>
```

`continue` 表示确认后继续业务任务，不表示无需预览确认。事实版报告需要用户明确接受资料缺失与未验证内容。正在执行、等待审批、压缩、下载附件、等待初始化、交给原生终端或已有待执行任务输入时不能接力；不会停止其他节点。暂停的编排任务可先交接后等待，执行需要明确恢复任务。

## 报告屏障与执行阶段

1. 生成预览时新增 preparing 阶段，原阶段仍是当前执行者。
2. 报告在现有 SessionReports 服务中异步生成。报告未 ready 时，目标 Agent 不执行任务。
3. 确认时核对记录范围、目录、设置、任务要求与当前绑定。预览后新增业务记录或配置发生变化，必须取消并重新准备。
4. 激活期间的新消息进入有界持久队列；当前 Agent、Session 当前阶段与 Task 的 Agent 在同一事务更新。
5. 原生上下文延迟到首次执行创建，界面显示等待首次启动；激活完成不等于原生上下文已经建立。
6. 首轮实际输入带来源阶段、报告版本、短摘要和完整报告读取入口。Agent 通过 `task_report_read` 读取同一授权 Session 的报告全文；摘要提交不等于全文已读取。

交接输入只在新阶段首次提交，后续轮次使用该阶段的原生上下文。实际输入快照进入 Web 历史，与用户消息、公开输出和工具记录共同展示。对话按阶段标注，可选择只查看某个执行阶段；历史未登记的事件仅在全部范围显示，不猜测归属。旧阶段的迟到回调不能改写新阶段的原生 ID、用量或输出，旧待办保留为历史上下文。

## 一个报告，多种用途

关闭总结、主动阶段总结和 Agent 接力共用 `session_reports`，不另建 handoff 报告表。报告保留任务状态、产物、规格或研究口径、验证依据、风险、剩余工作、下一步和有来源的经验。来源阶段、证据范围、有效指令和上一版报告用于接续；长历史截断时保留资料限制，不编造未采集内容。

相同任务快照已有 ready 报告时可以复用。生成来源不改写，用途记录另行关联关闭或目标阶段。报告正文、投递通知和原生输入提交是不同状态，不把聊天通知成功当成模型已收到。

摘要直接显示上限由 `handoffInlineLimit` 控制，默认 50 个 Unicode 字符；完整内容可在报告文档中查看。Agent 的首轮也使用摘要与报告索引，按需读取结构化全文。

接力报告不自动回传为最终交付、不唤醒父任务，也不放行下游依赖。关闭会话不代表目标完成。下游仍需上游验收完成及对应版本报告，TaskJob 固定所使用的报告版本。

## 持久化与用量

`agent_stages` 每行保存一个执行阶段及其轻量接力状态：Agent、nativeId、设置、来源阶段、输入报告、幂等 key、快照指纹和队列。Session 的 currentStageId 指向当前阶段，agent/nativeId 是当前投影。不单独增加 agent_handoffs 表。

新事件和用量轮次关联 stageId；旧事件没有可靠归属时留空，不按时间猜测。任务累计用量保留跨阶段消耗；当前上下文只使用当前原生会话的数据，接力次数与重置次数分别记录。切换会清除旧阶段的模型缓存、原生指令快照与自动允许策略，目标阶段使用自己的能力和审批模式。

审批策略覆盖在接力时清除。Codex/TRAE CLI 按框架默认使用 `on-request`；Claude Code、OpenCode、Antigravity CLI 沿用自己的原生默认配置，不接收其他 Agent 的模式名称。新阶段需要调整授权时使用本会话的审批策略入口。

首次登记已有数据前，在数据目录的 backups 中创建权限 0600 的 SQLite 快照。登记保持现有 Session/nativeId、聊天绑定与会话更新时间，不重放任务。阶段属于内部执行历史，不新增任务树节点。

已有任务节点重置继续保留逻辑 Session，并开始新的原生上下文阶段，不注入上一阶段的接力报告。尚未登记为任务的独立会话仍保留其既有重置行为；历史重置产生的 Session ID 不追改。关闭后重新打开会保留现有恢复语义，并单独登记后续阶段。

## 失败与人工核对

报告未就绪、预览过期或激活前失败，原绑定保持不变。激活后的执行失败保留新阶段，不自动退回旧 Agent，也不重放可能已生效的业务操作。

原生输入缺少提交确认，或提交期间服务重启，会显示 unconfirmed，后续执行被阻止。核对原生历史后，明确选择已收到或允许下一轮重试：

```text
/tab relay acknowledge-input <阶段ID>
/tab relay retry-input <阶段ID>
```

队列中的 processing 记录在重启后变为 unconfirmed，不自动重放。可在网页查看原文并处理，或使用：

```text
/tab relay resume-queue <阶段ID>
/tab relay retry-queue <阶段ID>
/tab relay dismiss-queue <阶段ID>
```

resume-queue 只恢复尚未执行的消息；retry-queue 是用户核对后允许重试未知消息，可能重复操作。dismiss-queue 明确放弃队列。恢复目的地是本 Session 当前 Agent，不会跨聊天重定向；原权限和绑定仍需有效。
