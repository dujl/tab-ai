# 工具审批与执行记录

## 存储与职责

本机框架使用配置 `dataDir` 下的 `state.sqlite`，默认位置为 `~/.tab-ai/data/state.sqlite`。`Store` 以 SQLite WAL 模式运行，目录权限 0700、数据库权限 0600。审批与工具事件统一追加到 `events` 表，字段为 `id`、`session_id`、`type`、`text`、`at`；结构化内容以 JSON 字符串存入 `text`，时间为 Unix 毫秒。

| 事件类型              | 内容与用途                                                                             |
| --------------------- | -------------------------------------------------------------------------------------- |
| `interaction`         | 审批/提问请求：UUID、所属会话、标题、详情、创建及截止时间、可读摘要                    |
| `decision`            | 用户提交的决定，使用同一请求 UUID 关联；`allow: true/false` 表示允许/拒绝              |
| `usage`               | 原生上报的模型输入、缓存输入、输出 token 统计；无上报时不猜测命中                      |
| `interaction_timeout` | 超时及通知会话；不会自动批准                                                           |
| `interaction_closed`  | 交互请求终态：允许、拒绝、已回答、超时或取消；每次交互只结算一次                       |
| `tool`                | 工具快照：轮次 UUID、原生工具 ID、名称、状态、输入、输出、退出码（是否存在依原生上报） |

`Manager.ask()` 创建审批并落库；`Manager.answer()` 校验所属会话、时效和答案后记录决定，将决定送回原生 Agent。结束或取消由 `finish()` 记录终态。等待中的 Promise、回调和计时器保存在 Manager 内存中，重启不会恢复旧授权，也不会自动执行待批命令。

`ToolProgress.record()` 接收原生适配器上报并追加快照，`finish()` 收口仍未结束的工具。卡片与网页从这些数据生成，卡片不是唯一存储。允许审批与执行成功分别呈现，二者没有可靠工具 ID 关联时，不按时间或命令文本猜测绑定。

## 标识与查询范围

- 审批 ID 是框架生成的请求 UUID，用来关联决定、超时、终态；旧卡片不能重复批准。
- 轮次 ID 是框架生成的 UUID。原生工具 ID 可能跨轮次复用，因此工具记录以 `(runId, toolId)` 去重，只展示最新快照。
- 数据库事件 ID 是递增整数，用于时间顺序、分页定位；卡片里的工具序号只是最近一轮的展示序号。
- `/tab tools [序号]` 沿用最近一轮查询；Dashboard 的“审批与执行”查当前任务的完整框架记录，支持 ID/关键词搜索及游标分页，不受对话页最近 200 条限制。

每页默认 30 条、最多 50 条，加载更早记录后可点刷新回到最新列表。搜索范围为相应记录的已存 JSON；审批状态从同一会话的终态/决定/超时事件关联得出。旧版缺失最终结果的请求标记“已结束，结果未记录”，不会根据截止时间推定失败，也不将其伪装为等待中或成功。

工具名称最多保存 100 字符、输入和输出各最多 8000 字符，超过后保存截断提示；原生 Agent 可能已做进一步裁剪或未上报结果。Dashboard 展开的是已保存内容，不能恢复未保存的完整输出。事件表没有自动按时间删除策略；群消息临时上下文和去重回执的清理策略不适用于审批/工具事件。备份应包含完整数据目录，运行中需考虑 WAL，详见运行文档。

## Dashboard

选中任务 → **审批与执行** → **审批记录 / 工具执行**。待处理问题与审批显示在页首，可提交本次决定；历史条目只读，展开查看 ID、时间、原始请求、输入、输出和退出码。总览“需要你处理”及任务对话页保留原有审批入口。

前端复用既有静态资源，并依据 `/api/state.executionRecords` 能力标记启用历史查询；等待空闲升级时保留当前审批操作，避免新旧版本交错导致页面加载失败或请求不存在的接口。

记录接口沿用 Dashboard bearer 认证与 Host/Origin 校验；持有实例管理令牌可查看全实例，不向聊天用户开放跨会话权限。历史查询不调用模型，不执行工具，也不唤醒 Agent。

审批范围、策略与临时授权生命周期见 [本会话审批](session-approvals.md)。新决定可包含 `scope: "session"` 或 `cancel: true`，历史页会展示实际提交的范围；查看授权记录不等同于授权仍有效。

旧 Codex 会话可按 nativeId 只读补查原生 Token 统计，网页执行记录与聊天菜单共享相同的来源和采样时间。历史补读不新增工具/审批记录，也不改变会话、任务或原生历史；不能可靠确定归属的旧 usage 事件不会直接当成当前上下文。详见 [管理卡片](management-cards.md#旧会话的原生统计读取)。
