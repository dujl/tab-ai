# 跨通道管理菜单

管理分为两个完全独立的卡片入口：`/tab menu` 为“本会话设置”，`/tab admin` 为“会话管理中心”。后者及会话列表仅在 Manager BOT 的已授权单聊提供；群内隐藏入口，直接命令和旧卡片也校验相同条件。本会话设置在原聊天使用；群模式为 auto 时无需 @，mention/context 时需 @。查询菜单不会调用工作 Agent，也不会创建空白会话。整体原则见[设计原则与实现](design-principles.md)。

管理卡片按用户主动调用显示，不随每条普通聊天或附件分析自动发送。普通消息的路由、查找或下载问题使用文字提示；缺少/不明确的附件是正常澄清，不当作异常，不附带模型/目录/重置等管理按钮。审批仍使用已有审批卡片。企微群的前置 @寻址后可直接使用管理命令，不会误交给工作 Agent。

“本会话设置”由只读的**会话信息**和独立的**会话管理**两区组成。名称放在卡片副标题；信息区紧凑展示“状态与 Agent、模型、思考深度与审批策略、完整目录、上下文与 Token 消耗”，字段标签和值同行、内部间距 4px；标识、原生终端恢复方式、父任务/通道和附加指令摘要折叠到更多信息。首屏模型/思考使用已保存值或“原生默认（未上报）”，配置来源与完整说明放入折叠详情，不猜测原生实际值。信息区没有隐式修改输入框。

常用操作按“压缩会话、重置会话…、模型与思考、工作目录”排列；重置先进入确认面板。飞书首页按运行状态前置处理待办、停止当前轮/压缩、恢复会话或查看终端交回方式。首页另有“审批与执行”“任务与交付”“更多操作”三个分组，具体功能最多两次导航可达：审批/工具/原生待办，当前分支/本任务交付报告/可复用经验，以及关闭/持续任务/对话/附件/名称/指令/终端。跨会话和 BOT 权限入口不混入本会话。

`/tab card` 与 `/tab menu` 打开同一菜单；初始化仍提供专门的首次设置表单，已初始化的持久状态卡也复用同一信息和首页操作。飞书采用 Card JSON 2.0，两列按钮、折叠详情、独立编辑面板。模型先选择再提交档位表单，选择不改保存值；无档位模型只提供保存按钮。目录面板预填当前目录，三行输入框独立靠上展示；留空保留当前目录。表单不能放入折叠面板，提交由组件 name 标识服务端动作，原生按钮使用 callback behaviors。飞书“返回本会话/管理中心”为带边框的可点击按钮，不使用灰色文字样式。所有菜单底部提供蓝色文字链接 [tab-ai ↗](https://github.com/dujl/tab-ai) 直达链接，文字通道保留完整 URL。

菜单内导航和操作结果尽量替换原飞书消息，并撤销上一版按钮；直接发命令仍建立新的查询面板。用户接管后的面板不被后台状态卡刷新覆盖，保存/返回/手动刷新才读取新快照。压缩的受理和最终结果复用同一面板，颜色明确区分等待、成功、失败或未确认。审批和问答卡片独立处理，不因菜单导航自动批准。

“会话管理中心”首页依次为“会话列表”“目标详情”“停止目标任务”“结束／恢复”。目标操作先选择有权访问的 session，再显示目标名称、完整 ID、状态和相应动作；不默认套用当前会话。“更多管理”提供概览、目标历史和工具、新建会话/任务、任务树与机器人设置；群接收模式仅在实际飞书群内操作。目标动作仍保留原有权限范围，不提供跨会话模型、目录、重置或压缩。新建会话是用户主动创建入口，不复用重置操作。

两类卡片的导航和默认结果按钮分别返回本会话或管理中心，不互相跳转。每张企微菜单最多四个内容操作，加一个独立的“更多/返回”和一个“查看全文”，符合 SDK 最多六个按钮的限制；导航不会挤占四个优先入口。完整说明 `/tab help` 属于管理中心。

| 通道               | 管理展示与操作                                                               | 需要填写参数时                                                          |
| ------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 飞书               | Card 2.0 信息/管理分区、两列按钮、折叠详情及独立编辑表单                     | 原生表单，或明确显示的文字命令                                          |
| 企业微信智能机器人 | 原生按钮模板卡片；长内容先摘要，可点“查看全文”；设置、目录、会话分页均可点击 | 预设目录按钮、模型/档位选择；自定义目录、名称、任务目标通过文字命令输入 |
| 钉钉 Stream 机器人 | 无需租户卡片模板的 Markdown 管理菜单，显示可复制的命令                       | 在原聊天复制命令填写参数；已有审批卡片仍按租户模板配置使用              |
| 微信               | 带会话标记的文字菜单和完整命令；引用入口保留子会话路由                       | 复制命令填写参数                                                        |

企微和钉钉并非完全不支持卡片。这里按当前具体连接方式的能力适配：企微模板没有通用文本输入框、不能任意主动更新旧卡，因此每次管理查询发送新的快照菜单；钉钉已有审批模板不具备通用管理动作的模板契约，不把审批按钮伪装成会话管理按钮。

## 功能入口

- 重置：`/tab reset` 打开说明面板，确认按钮绑定当前会话 ID 和状态版本；查看面板不会重置。确认后在原聊天/话题建立新会话，保留 Agent、目录、模型、附加指令及原生开发者指令快照；不继承原生 ID、旧 Agent 对话、待执行任务或待处理附件。旧会话关闭且历史保留，可通过会话列表查看、显式恢复。重置本身不调用模型，下一条任务才创建新原生上下文。运行、审批、下载、自然语言路由处理中或原生终端占用时拒绝；编排任务重置保留 Task/Session ID 和关系，只重置本节点原生上下文。旧确认、重复点击和绑定变化不会重置新会话。显式配置的群聊参考仍遵循通道自己的规则，重置不关闭群上下文能力。
- 会话状态、关闭/恢复、停止、历史、工具、附件和待审批：`/tab status`、`/tab close`、`/tab open`、`/tab stop`、`/tab history`、`/tab tools`、`/tab files`、`/tab pending`。
- 会话列表：`/tab list [页码]`，页码从 1 开始，企微每页 2 条、其他通道每页 6 条；企微模型列表也每页 2 条，保证翻页和返回按钮之外的每条结果均可点击。管理中心的目标选择器每页 2 条。列表在有权访问的范围内跨话题展示，操作不会改绑原聊天。
- 目录：`/tab workspace` 显示当前目录及预设按钮；`/tab workspace <本机目录或别名>` 输入自定义目录。保留上下文的迁移规则不变，不支持的后端明确拒绝。
- 模型：飞书使用独立的模型选择和明确提交档位表单；企微、钉钉、微信可在原聊天 `/tab settings` 读取实际能力，选择模型后选择档位并保存。列表支持 `/tab settings page <页码>`、`/tab settings refresh`。显示的 `choose` 及 `apply` 命令可直接复制；内部 URI 编码保留模型 ID 的特殊字符，保存命令携带设置版本，旧版本拒绝覆盖。
- 名称：飞书“更多操作 → 修改名称”使用独立表单，预填当前名称，1～60 个字；明确保存才更新，取消保留原值。仍校验原发起人、聊天、会话绑定和版本，运行中不可保存。无输入组件的通道保留 `/tab rename <名称>`。
- 创建/改名/任务目标：`/tab new [Agent]`、`/tab init [Agent]`、`/tab rename <名称>`、`/tab task <目标>`。没有输入框的通道显示明确的填写方式，不把占位文字当成真实任务执行。
- 任务、机器人角色和群模式沿用既有命令与权限边界，管理结果采用通道对应的展示。机器人角色提升和群模式设置不会因查看菜单自动执行。

## 回调与投递边界

卡片回调只有随机 ID 和动作序号，命令、作用范围、原聊天路由、会话和权限上下文保存在服务端。只接受原聊天的菜单发起人；飞书还校验原卡片消息 ID。每次操作重新检查白名单和权限。本会话修改操作检查当前绑定和状态版本；跨会话操作检查明确选中的目标、目标访问权限及目标会话/任务快照版本，不依赖投递入口当前绑定哪个 session。重复修改拒绝执行，旧菜单不会误改新会话。管理中心回复留在发起管理操作的原聊天/话题，不将查询回复投递到目标私聊。菜单有效期 15 分钟，最多保留 200 张；重启后分别用 `/tab menu`、`/tab admin` 打开。

飞书回调立即返回 toast，企微先响应卡片回调再执行动作；查询能力目录不开始模型任务。卡片被平台明确拒绝时，可安全降级为 Markdown/文字；网络中断或成功与否未知时不自动补发，防止重复通知。按钮不可用或旧菜单过期时仍可在原聊天发送完整管理命令。

当前验收覆盖隔离 SDK/HTTP 模拟回调和完整权限链；真实客户端排版与租户权限仍以对应平台的实际接入为准。接口参考：[钉钉自定义机器人](https://open.dingtalk.com/document/robots/custom-robot-access)、[企业微信模板卡片](https://developer.work.weixin.qq.com/document/path/101032)及本机安装的 `@wecom/aibot-node-sdk` 类型定义。

## 原生会话压缩与循环控制

“压缩会话”位于本会话首页，飞书“持续任务管理”位于首页“更多操作”中；企微在“更多本会话 → 更多操作 → 持续任务与终端”中提供，按平台按钮上限分组。Dashboard 的会话工具栏也提供压缩与循环控制入口。接口与文字命令保持相同权限及目标 ID 校验。

| 操作              | 入口                                     | 实际行为                                                   |
| ----------------- | ---------------------------------------- | ---------------------------------------------------------- |
| 查看压缩面板      | `/tab compact`（别名 `/tab compaction`） | 显示能力、占用状态和原生压缩说明                           |
| 执行压缩          | `/tab compact start`                     | 异步调用原生 compaction；不是普通工作提示或清空会话        |
| 查看自动继续项    | `/tab loops`（别名 `/tab loop`）         | 列出当前会话已接通的任务树调度及 Codex goal                |
| 停止所选项        | `/tab loops stop <ID>`                   | 按类型暂停任务树，或清除当前原生 goal 并等待对应当前轮中断 |
| 停止当前轮 / 压缩 | `/tab stop`                              | 中断当前执行；不会自动取消其他周期任务                     |

压缩使用 Codex `thread/compact/start`、Claude SDK 的原生 `/compact`、OpenCode 的原生 `/session/:id/summarize`。压缩需要模型调用；只收到受理回执不算完成，须分别确认 `contextCompaction` 完成、`compact_boundary`、新的原生摘要消息。内容不足、登录失败、超时或中止均明确报告，不自动重试。

压缩保留管理/原生会话 ID、目录、模型设置、附加指令及框架历史；原生较早上下文会总结，不能保证逐字细节全部保留。已有关闭会话压缩后仍关闭，运行/等待审批/终端占用/下载时拒绝压缩。同一会话只允许一个工作或压缩操作；任务调度不能在压缩中启动下一轮。服务重启清理中断标记，不自动重复模型调用。

循环管理的范围：

- **任务树自动调度**：持久化 `paused`，阻止当前任务及其子任务继续领取队列，再等待已运行轮次中断；待处理资料和原生上下文保留，可通过已有任务恢复命令显式继续。
- **Codex 原生 goal**：使用当前运行进程的 RPC（空闲时恢复同一线程），读取目标身份，调用 `thread/goal/clear` 并带 `origin: user`，再次确认目标为空。原生目标取消未确认时，不把中断当前轮当作取消成功；旧目标 ID 不能清除不同的新目标。
- **Claude Cron `/loop`、外部脚本及插件循环**：当前未接入确定性的枚举/取消协议，面板明确提示原生入口；不会扫杀进程、删除调度配置或借用工作模型猜测“已经停止”。Claude 固定周期 loop 的取消与中断当前轮不同，需原生 CronDelete 等能力；本工程每轮 SDK 连接会关闭，也不承诺原生后台循环在两轮之间持续运行。

原生资料：[Codex App Server](https://learn.chatgpt.com/docs/app-server#trigger-thread-compaction)、[Claude SDK 压缩](https://code.claude.com/docs/en/agent-sdk/slash-commands#compact-history-with-compact)、[Claude loop 停止规则](https://code.claude.com/docs/en/scheduled-tasks#stop-a-loop)、[OpenCode Server](https://docs.opencode.ai/docs/server/)。适配能力与真实原生登录应分别按 [验收](acceptance.md) 核对。

## 管理卡片投递与压缩诊断

飞书管理消息每个分片生成独立 UUID，临时网络故障、HTTP 429/5xx 或飞书限流码 `99991400` 最多尝试 3 次（间隔 500/1500 ms），每次复用相同 UUID、正文和原话题。永久拒绝或成功响应缺少消息 ID 时不盲目重发。失败后撤销该卡片的管理按钮，在原话题发送带命令的文字入口；文字投递也复用自身 UUID 有限重试。无法确认原话题时不会改投群顶层或单聊。以上只重试投递，不执行或重试卡片里的动作。

投递失败写入当前 session 的 `delivery_error` 事件，字段包含诊断 ID、action、目标 session、stage、结果、尝试次数，以及平台返回的安全错误码、HTTP 状态、网络类别和可获得的请求 ID。文字兜底成功另写 `management_delivery`，失败写独立阶段事件。平台未返回对应字段时不补造；不保存 SDK 原始响应、认证头、URL 或 stderr。

`/tab compact` 只查看面板，`/tab compact start` 经明确确认后才执行。每次执行分配操作 ID，按 `accepted → running → completed/noop/failed/unconfirmed` 写入 SQLite `events` 表，type 为 `compaction`、text 为 JSON，包含时间和安全原因分类，可附原生数字 RPC 错误码。只有适配器确认原生完成标记才为 completed；原生拒绝、无需压缩和结果不确定分别展示。停止、超时、重启均不会自动重跑，重启会把未完成执行标为失败或未确认。阶段中的 running 包含原生适配器恢复线程和调用压缩的过程。

聊天面板与 Dashboard 的压缩弹窗可查看最近阶段、原因及操作 ID；Dashboard 提交后保留面板，通过刷新读取执行结果。框架历史、同一原生会话 ID、目录和模型设置保留。未知原生错误仅给安全分类和可用错误码，不把可能包含凭据的原文发回聊天。

## Token 用量与压缩对比

本会话信息紧凑显示“上下文”和“Token 消耗”，详情保留最近调用的输入、缓存读取、缓存写入、输出、更新时间与统计口径。压缩结果和 Dashboard 压缩面板显示同一次操作的前后 tokens；只有两端都上报时才计算变化。累计消耗不会因压缩减少，压缩本身也可能消耗 tokens。原生估算不是账单，不根据字符数补造数据。

- Codex：采集 `thread/tokenUsage/updated` 的 `last.totalTokens`、`modelContextWindow` 与 `total`；上下文是最近原生统计/估算，累计是原生会话累计。独立压缩连接采集恢复时的基线与压缩轮次最后的有效统计，并等待完成标记。
- Claude Code：普通调用使用主 Agent 消息的 usage 作为最近调用参考；result.modelUsage 保持原生调用累计口径，不累加重复快照。手动压缩优先使用 `compact_metadata.pre_tokens/post_tokens`；旧版本不提供 post_tokens 时等待后续原生统计。多模型时不猜测当前窗口容量。
- OpenCode：展示最终响应的 tokens，缓存与 reasoning 按原生字段归一化为最近调用参考；不把它冒充整会话累计。summarize 的摘要调用用量不是压缩后的上下文，未获得后者时显示待更新。

已有 Codex 会话会按当前 nativeId 只读补查原生历史统计，优先使用较新的有效样本，展示来源和采样时间；无需重新执行任务或调用模型。只有上报窗口容量才展示占比，缺失显示“未上报”；零是有效数值。压缩完成但缺少新计数、或超时/中止/重启结果未确认时，旧上下文占用不再作为当前值展示。累计、历史与会话标识保留；重置或更换原生会话后不复用旧计数。

“停止压缩”是请求中止正在执行的原生操作，不是撤销摘要：Codex 关闭本次独立 app-server，Claude 使用 SDK AbortController，OpenCode 在未确认完成时调用 session abort；已写入的原生摘要无法由此回滚。中止后未确认完成则如实标记 unconfirmed，不承诺恢复原上下文。

实现口径参考 [Codex 压缩后重算用量](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs) 与 [OpenCode 用量归一化](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/session.ts)，并以安装版本实际上报字段为准。

### 旧会话的原生统计读取

Codex 适配器提供可选的 `historicalUsage` 能力：遵循本进程 CODEX_HOME（未设置时为 ~/.codex），只读查询原生 state 数据库定位 rollout，数据库不可用时从 sessions/archived_sessions 文件名索引寻找。读取前校验原生记录 session_meta.id 与目标 nativeId 完全相同，路径位于原生历史目录；只解释 token_count 与 compaction 标记，不展示原始对话内容。

读取以文件签名缓存，最多扫描文件头 1 MiB 和末尾 4 MiB，文件发生追加时重新采样；过大元数据、缺失或不兼容记录不阻断菜单。原生上下文 total_tokens 独立于 input/output 字段，压缩后即使输入和输出计数为零也保留非零上下文。发现 compacted 后尚无新 token_count 时，旧占用不再当作当前值；框架中止/超时标记还要与采样及原生压缩时间校验。

历史补读是展示覆盖层，不写回会话，不修改 recency、任务状态、管理 revision 或原生历史。聊天菜单、持久状态卡和网页维护/执行记录共享该覆盖层；压缩前基线也可使用已验证的历史样本。其他 Agent 未提供此本地历史能力时继续使用已采集的原生事件，不套用 Codex 的目录或文件格式。
