# 设计原则

框架负责可信入口、任务关系、生命周期、交互与持久化；原生 Agent 负责推理、工具执行、登录和自己的对话历史。操作见 [会话手册](sessions-guide.md)，模块职责见 [架构](architecture.md)。

## 统一任务，保留独立状态

Task 是统一工作单元，Session 是该节点的内部原生上下文。有没有子节点不决定任务类型；只交互与编排是执行能力差异，不要求用户在两个列表间选择。

Task 的目标完成、Session 空闲/关闭、审批允许、工具执行成功、报告可用分别记录。阶段准备、通过一次测试、一轮结束都不能直接标为整个目标完成。

## 原生运行时与上下文

沿用原生登录、项目规则、工具、模型及权限机制，保存并核对 nativeId。Codex 默认按需审批，可按 Session 明确选择其他受支持策略；设置不扩展原生沙箱权限。临时授权不跨 Session。

有效背景组合原生指令、可信通道背景和显式会话附加指令。群参考、任务简报、下级报告作为明确标注的资料，不赋予权限、不复制完整聊天、不包含私有推理。未知平台类型不自行推断；在线文档默认产品来自实际通道，用户明确指定的平台优先。

## 管理与工作分开

`/tab`、卡片动作、授权和状态变更由框架执行；不能以 Agent 的口头“已切换”代替实际 cwd 或配置变化。普通网页对话用于工作，管理使用工具栏/API。

自然语言管理使用独立受限分类器，字段经 schema、原文依据和绑定检查。明确管理操作无法确认时要求澄清或使用命令；分类服务暂不可用时，普通工作请求继续原 Session，明确附件要求进入附件流程。分类等待最多 10 秒，服务故障冷却 30 秒；不把错误决定当成授权。

## 路由与授权来自可信入口

平台、Bot、聊天、分支和发送者共同限定上下文。回复留在原路由，未知引用不猜测投到主会话，不因群消息失败改发单聊。

| 能力             | 范围                                                       |
| ---------------- | ---------------------------------------------------------- |
| 工作与本会话设置 | Bot 已授权用户及当前绑定 Session                           |
| 主会话下级总览   | 本 Bot、聊天、用户与本分支，无需 Manager                   |
| 全局管理中心     | Manager Bot 已授权用户，且在经平台确认的 Bot 单聊          |
| 审批与答题       | 原发起人、原聊天/卡片及有效期限；Manager 不替代此身份      |
| 原生任务工具     | 当前有效轮的能力令牌，按本任务/直接子任务/报告依赖范围校验 |
| Dashboard        | 本机 bearer 全局管理权限，不提供聊天用户 RBAC              |

菜单隐藏不能代替执行检查。修改绑定目标与版本；重复点击、过期请求、转发和分类期间改绑不得误操作。会话设置和全局管理保持独立入口。本会话卡片将只读信息与显式管理操作分区；选项作为草稿，确认保存才变更配置，未知原生值不得伪造。每张管理卡片提供项目 GitHub 直达入口。

## 树形协作与交付

每个节点有独立原生 Session；新子任务默认继承直接父级工作目录，已有节点切目录不影响其他节点。共享文件不等于共享上下文；没有自动 worktree、文件锁或冲突合并。

父 Agent 决定拆分，框架持久化队列、同级依赖和验收版本。阶段进展留在当前节点；整体成果提交后由直接父级验收。新增下级、补充工作或修改成果使相关祖先的当前结论失效，历史报告仍可追溯。

关闭、取消和提交成果触发版本化交付报告。下游依赖已验收的成果和匹配报告，记录所用版本；经验必须有来源、适用条件与限制。公开历史截断和总结故障降级明确展示。详见 [报告与经验](session-reports.md)。

## 默认值必须与执行一致

表单显示 Session 已保存的目录；留空保留当前值，不以全局默认覆盖继承值。Bot 默认目录只作用于以后新节点。

切目录在当前绑定、空闲、无待处理输入时执行。已有原生历史要求适配器明确支持，实际下一轮 cwd 由后端校验，不创建替代上下文。重置与压缩含义不同，详见 [会话管理](session-management.md)。

## 按平台实际能力呈现

飞书群 mention/context/auto 覆盖群顶层与话题，前提是实际消息权限生效；单聊直接接收，无群模式切换。企微白名单群按需补读不等于全量实时订阅。

管理菜单主动请求时展示。审批、提问与工具进度按真实事件展示；卡片首屏给可读摘要，原文可查看。文字和颜色共同表达状态，批准不能显示为执行成功。不支持控件时提供该通道可用的文字入口。

上传附件先登记，明确要求处理后才下载；最近附件指代、引用与候选选择由框架解析，下载/解密由实际 Channel 完成。缺少附件正常澄清，不发管理菜单或让用户反复选择。

## 持久化与恢复

数据库事务保护关联写入，目录锁保护同一实例；外部消息或文件副作用不能与 SQLite 组成分布式事务。结果未知时不盲目重发，不把恢复原生历史当作 exactly-once 执行。

重启保留历史和关系，正在执行的工作标为中断，未执行队列按依赖和权限恢复。旧审批不恢复批准能力；总结队列可恢复同一报告版本。读取线上状态用 API 或只读数据库连接。

新行为同步修改代码、API、指南与可观察的回归。文档写当前契约，机器相关证据单独保存；验证方法见 [验收](acceptance.md)。
